# ТРЕБОВАНИЯ К API {#ar}

## AR-001. Общие правила API {#ar-001 .collapsed}

- **Использует**: [error.response.schema.json](api/error.response.schema.json)
- **Используется в**: все операции API продукта, в том числе [AR-PT-001][] и операции справочника видов изделий
- **Описание**: Правила, одинаковые для всех операций API: форматы, порядок проверок, коды ошибок и общие эталоны
ответов с ошибкой. Операция описывает только то, что у неё отличается.

### Запрос и ответ {#ar-001-format .collapsed}

- **Базовый путь**: `/api/v1`.
- **Тело**: JSON в кодировке UTF-8, заголовок `Content-Type: application/json` у запросов с телом.
- **Идентификаторы**: UUID в нижнем регистре.
- **Дата и время**: ISO 8601 в UTC с точностью до секунды, `ГГГГ-ММ-ДДTЧЧ:ММ:ССZ` ([NFR-004][]).
- **Числа**: JSON-числа; в строке запроса — с точкой (`0.5`).
- **Логические значения**: `true` и `false`.
- **Отсутствие значения**: `null` в теле и пустой параметр строки запроса (`search=`) приравниваются к отсутствию
  поля или параметра.
- **Лишнее**: поле тела вне состава запроса — ошибка `UNKNOWN_FIELD`; параметр строки запроса вне перечня операции —
  `UNKNOWN_PARAMETER`; повтор параметра — `DUPLICATE_PARAMETER`.
- **Аутентификация**: обязательна для всех операций; способ определяет технический стандарт.

### Порядок проверок {#ar-001-order .collapsed}

Система проверяет запрос в таком порядке и отвечает по первой непройденной проверке:

1. Аутентификация — `401`.
2. Право на операцию — `403`.
3. Формат идентификаторов в пути, параметры и тело запроса — `400`; в ответе перечислены все найденные ошибки, а не
   только первая, в порядке полей или параметров из описания операции.
4. Существование записи — `404`.
5. Правила предметной области (одновременное изменение, уникальность, использование записи) — `409`; порядок этих
   проверок задаёт операция.

Внутренняя ошибка на любом шаге — `500`. При любом отказе система не меняет данные и не пишет в журнал аудита.

### Ответ с ошибкой {#ar-001-errors .collapsed}

Тело ответа с ошибкой соответствует схеме [error.response.schema.json](api/error.response.schema.json): код `code`,
сообщение `message` и, для ошибок в данных, перечень `details` с полем, кодом и сообщением.

- `message` и `details[].message` — на русском языке, для пользователя, без технических подробностей: стека
  вызовов, текста SQL, имён таблиц и классов.
- `details[].field` — имя поля тела или параметра; для элемента массива — с индексом: `pks[0]`.

| Код ответа | `code` | Когда | Эталон |
| :--- | :--- | :--- | :--- |
| `400` | `VALIDATION_ERROR` | Ошибки в параметрах или теле запроса | Задаёт операция |
| `401` | `UNAUTHORIZED` | Пользователь не аутентифицирован | [error.401.json](api/error.401.json) |
| `403` | `FORBIDDEN` | Нет права на операцию | [error.403.json](api/error.403.json) |
| `404` | `NOT_FOUND` | Записи нет | Задаёт операция |
| `409` | Задаёт операция | Нарушено правило предметной области | Задаёт операция |
| `500` | `INTERNAL_ERROR` | Внутренняя ошибка | [error.500.json](api/error.500.json) |

Ответы `401`, `403` и `500` одинаковы для всех операций: операции и их критерии приёмки ссылаются на общие эталоны,
а не хранят копии.

### Коды ошибок в `details` {#ar-001-detail-codes .collapsed}

| Код | Значение |
| :--- | :--- |
| `REQUIRED` | Обязательное поле или параметр не передан |
| `INVALID_TYPE` | Значение не того типа (не строка, не число, не целое, не логическое) |
| `INVALID_VALUE` | Значение не входит в перечень допустимых |
| `INVALID_FORMAT` | Значение не соответствует формату (UUID, дата и время) |
| `INVALID_SCALE` | Больше знаков после точки, чем допускает поле |
| `INVALID_RANGE` | Начало диапазона позже его конца |
| `INVALID_COMBINATION` | Параметр передан без параметра, от которого зависит |
| `OUT_OF_RANGE` | Число вне допустимых границ |
| `BLANK` | Строка пустая после обрезки пробелов по краям |
| `TOO_LONG` | Строка длиннее допустимого |
| `EMPTY` | Пустой массив |
| `TOO_MANY` | В массиве больше элементов, чем допустимо |
| `DUPLICATE` | Значение повторяется: в массиве запроса или среди записей (уникальность) |
| `IN_USE` | Запись используется в других сущностях |
| `UNKNOWN_FIELD` | Поле тела вне состава запроса |
| `UNKNOWN_PARAMETER` | Параметр строки запроса вне перечня операции |
| `DUPLICATE_PARAMETER` | Параметр строки запроса передан больше одного раза |

Новый код добавляется в эту таблицу до того, как операция начнёт его возвращать.

### Критерии приёмки (AC) {#ar-001-ac .collapsed}

Сценарии выполняются для каждой операции API; перечень операций справочника видов изделий — в примерах.

```gherkin
# language: ru
@AR-001
Функционал: Общие правила API

  Структура сценария: Пользователь не аутентифицирован
    Дано пользователь без аутентификации
    Когда он вызывает операцию "<операция>" с корректными данными
    Тогда код ответа равен 401
    И тело ответа равно содержимому файла "error.401.json"
    И данные не изменились

    Примеры:
      | операция                                   |
      | GET /api/v1/product-types                  |
      | GET /api/v1/product-types/{pk}             |
      | POST /api/v1/product-types                 |
      | PUT /api/v1/product-types/{pk}             |
      | POST /api/v1/product-types/batch-delete    |

  Структура сценария: Аутентификация проверяется раньше данных
    Дано пользователь без аутентификации
    Когда он вызывает операцию "<операция>" с некорректными данными
    Тогда код ответа равен 401

    Примеры:
      | операция                                   |
      | POST /api/v1/product-types                 |
      | PUT /api/v1/product-types/{pk}             |
      | POST /api/v1/product-types/batch-delete    |

  @manual @NFR
  Структура сценария: Внутренняя ошибка не раскрывает технических подробностей
    Дано хранилище данных недоступно
    Когда аутентифицированный пользователь с правом на операцию вызывает "<операция>"
    Тогда код ответа равен 500
    И тело ответа равно содержимому файла "error.500.json"

    Примеры:
      | операция                                   |
      | GET /api/v1/product-types                  |
      | POST /api/v1/product-types                 |
      | PUT /api/v1/product-types/{pk}             |
      | POST /api/v1/product-types/batch-delete    |
```
