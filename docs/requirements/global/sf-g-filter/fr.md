# ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ {#fr}

Критерии приёмки проверяются на каждом списке, который подключает функциональность. Эталонная реализация —
справочник видов изделий (`GET /api/v1/product-types`, экран «Виды изделий», приставка `data-testid` `pt`, поля
фильтра — в [FR-PT-LIST-006][]) с [тестовым набором][fixture].

## FR-G-FILTER-001. Фильтрация списка {#fr-g-filter-001 .collapsed}

- **Использует**: [SF-G-FILTER][], [AR-001][], [NFR-004][]
- **Используется в**: [UI-G-FILTER-001][], [FR-PT-LIST-009][]
- **Описание**: Операция списка отбирает записи по условиям на отдельные поля, переданным параметрами строки запроса.
- **Условие**: Пользователь вызывает операцию списка, которая подключает [SF-G-FILTER][], хотя бы с одним параметром
фильтра из перечня функциональности.
- **Результат**:
    - Параметр фильтра называется так же, как поле API; у периода — два параметра `<поле>_from` и `<поле>_to`.
    - Условие отбора зависит от вида условия поля (таблица ниже).
    - У периода можно передать одну границу; время — ISO 8601 в UTC ([NFR-004][]).
    - Все условия, включая поиск, объединяются по «и»; `total` считается с учётом всех условий ([SF-G-PAG][]).
    - Пустой параметр приравнивается к отсутствию фильтра ([AR-001][]); API не хранит фильтры между запросами.
- **Ошибки параметров** (ответ `400`, коды из [AR-001][]): значение не того типа — `INVALID_TYPE`; не из перечня —
`INVALID_VALUE`; число вне границ поля — `OUT_OF_RANGE`; лишние знаки после точки — `INVALID_SCALE`; неверный формат
даты — `INVALID_FORMAT`; начало периода позже конца — `INVALID_RANGE` в поле `<поле>_from`.

### Виды условий {#fr-g-filter-001-conditions .collapsed}

| Вид условия | Пример параметра | Условие отбора |
| :--- | :--- | :--- |
| Вхождение | `name=броши` | Значение поля содержит подстроку по правилам поиска [SF-G-SEARCH][] |
| Выбор | `product_group=JEWELRY` | Значение поля равно одному значению из перечня |
| Число, целое | `stamp_impressions_count=1` | Значение поля равно числу |
| Логическое | `is_active=false` | Значение поля равно `true` или `false` |
| Период | `created_at_from=…&created_at_to=…` | Не раньше начала и не позже конца, обе границы включаются |

### Критерии приёмки (AC) {#fr-g-filter-001-ac .collapsed}

```gherkin
# language: ru
@FR-G-FILTER-001 @SF-G-FILTER
Функционал: Фильтрация списка

  Предыстория:
    Дано в справочнике видов изделий записи из файла "PT.fixture.json"
    И аутентифицированный пользователь с правом просмотра списка

  Сценарий: Границы периода включаются
    Когда он запрашивает "GET /api/v1/product-types" с параметрами "created_at_from" = "2026-11-18T13:23:51Z",
      "created_at_to" = "2026-11-19T09:40:58Z"
    Тогда "total" равно 2

  Сценарий: Задана только одна граница периода
    Когда он запрашивает "GET /api/v1/product-types" с параметром "updated_at_from" = "2026-11-23T09:00:00Z"
    Тогда "total" равно 2
    И "items" содержит записи "Брелоки" и "Замки шпрингельные"

  Сценарий: Поиск и фильтр объединяются по «и»
    Когда он запрашивает "GET /api/v1/product-types" с параметрами "search" = "кольца", "default_streak_count" = 1
    Тогда "total" равно 1
    И "items" содержит только запись "Кольца обручальные"

  Структура сценария: Ошибка в значении фильтра
    Когда он запрашивает "<операция>" с параметром "<параметр>" = "<значение>"
    Тогда код ответа равен 400
    И "details" содержит ошибку с полем "<параметр>" и кодом "<код>"

    Примеры:
      | операция                  | параметр             | значение   | код            |
      | GET /api/v1/product-types | is_active            | yes        | INVALID_VALUE  |
      | GET /api/v1/product-types | product_group        | GOLD       | INVALID_VALUE  |
      | GET /api/v1/product-types | default_streak_count | abc        | INVALID_TYPE   |
      | GET /api/v1/product-types | default_streak_count | 0.555      | INVALID_SCALE  |
      | GET /api/v1/product-types | updated_at_from      | 23.11.2026 | INVALID_FORMAT |

  Сценарий: Начало периода позже конца
    Когда он запрашивает "GET /api/v1/product-types" с параметрами "created_at_from" = "2026-11-20T00:00:00Z",
      "created_at_to" = "2026-11-19T00:00:00Z"
    Тогда код ответа равен 400
    И "details" содержит ошибку с полем "created_at_from" и кодом "INVALID_RANGE"
```
