# ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ {#fr}

Критерии приёмки проверяются на каждом списке, который подключает функциональность. Эталонная реализация —
справочник видов изделий (`GET /api/v1/product-types`, поиск по наименованию, экран «Виды изделий», приставка
`data-testid` `pt`) с [тестовым набором][fixture].

## FR-G-SEARCH-001. Поиск по вхождению строки {#fr-g-search-001 .collapsed}

- **Использует**: [SF-G-SEARCH][], [AR-001][]
- **Используется в**: [UI-G-SEARCH-001][], [FR-PT-LIST-002][]
- **Описание**: Операция списка отбирает записи, у которых значение хотя бы одного поля поиска содержит строку
поиска.
- **Условие**: Пользователь вызывает операцию списка, которая подключает [SF-G-SEARCH][], с параметром `search`.
- **Результат**:
    - Система обрезает пробелы по краям строки; пустая после обрезки строка, как и пустой параметр (`search=`), не
      применяется.
    - Сравнение — по вхождению подстроки без учёта регистра.
    - Символы `%`, `_` и `\` ищутся как обычные символы, а не как шаблоны.
    - Поиск сочетается с фильтрами ([SF-G-FILTER][]) по «и»; `total` и страницы — по [SF-G-PAG][].
    - Совпадений нет — ответ `200` с пустым `items` и `total` = 0, а не ошибка.
    - API не хранит строку поиска: клиент передаёт её в каждом запросе, в том числе при переходе на другую страницу.
- **Ошибки параметров** (ответ `400`): длина строки после обрезки больше 150 символов (или иного предела
функциональности) — код `TOO_LONG` в поле `search`.
- **Схема**: определение `search` — в `global/api/list.schema.json`.

### Критерии приёмки (AC) {#fr-g-search-001-ac .collapsed}

```gherkin
# language: ru
@FR-G-SEARCH-001 @SF-G-SEARCH
Функционал: Поиск по вхождению строки

  Предыстория:
    Дано в справочнике видов изделий записи из файла "PT.fixture.json"
    И аутентифицированный пользователь с правом просмотра списка

  Структура сценария: Правила сравнения
    Когда он запрашивает "<операция>" с параметром "search" = "<строка>"
    Тогда код ответа равен 200
    И "total" равно <количество>

    Примеры:
      | операция                  | строка  | количество |
      | GET /api/v1/product-types | для     | 1          |
      | GET /api/v1/product-types | ДЛЯ     | 1          |
      | GET /api/v1/product-types | коль    | 3          |
      | GET /api/v1/product-types | %       | 0          |
      | GET /api/v1/product-types | Диадема | 0          |

  Структура сценария: Пробелы по краям обрезаются, пустая строка не применяется
    Когда он запрашивает "<операция>" с параметром "search" = <значение>
    Тогда "total" равно <количество>

    Примеры:
      | операция                  | значение   | количество |
      | GET /api/v1/product-types | "  коль  " | 3          |
      | GET /api/v1/product-types | ""         | 15         |
      | GET /api/v1/product-types | "   "      | 15         |

  Структура сценария: Слишком длинная строка
    Когда он запрашивает "<операция>" с параметром "search" из 151 символа
    Тогда код ответа равен 400
    И "details" содержит одну ошибку с полем "search" и кодом "TOO_LONG"

    Примеры:
      | операция                  |
      | GET /api/v1/product-types |
```
