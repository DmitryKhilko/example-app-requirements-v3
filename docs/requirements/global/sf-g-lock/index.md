## SF-G-LOCK. Защита от одновременного изменения {#sf-g-lock .collapsed}

- **Статус**: анализ
- **Приоритет**: must
- **Стабильность**: средняя — не подтверждены повторное чтение записи при открытии формы и поведение формы после
  отказа (`UI-G-LOCK-001.H01`, `H02`)
- **Права доступа**: определяет операция изменения, которая подключает функциональность
- **Использует**: [AR-001][], [NFR-004][], [SF-G-FORM][], [SF-G-TOAST][]
- **Используется в**: [SF-PT-UPDATE][], [SF-PT-ACTIVATION][]
- **Описание**: Оптимистичная блокировка: изменение записи принимается, только если с момента чтения её не изменил
другой пользователь; иначе пользователь получает отказ и не перезаписывает чужие изменения.
- **Границы**:
    - **Входит**: Версия записи в запросе изменения, проверка и отказ `409 RECORD_MODIFIED`, поведение формы при
      отказе.
    - **Не входит**: Пессимистичная блокировка (запись не блокируется на время редактирования), слияние изменений,
      показ того, кто изменил запись.

### Состав требований {#sf-g-lock-content .collapsed}

| Требование | Что описывает |
| :--- | :--- |
| [FR-G-LOCK-001][] | Проверка версии записи (API) |
| [UI-G-LOCK-001][] | Форма при одновременном изменении |

### Как подключить {#sf-g-lock-usage .collapsed}

Операция изменения включает `updated_at` в обязательные поля запроса, ставит проверку версии в порядок проверок
после существования записи и до других правил предметной области и ссылается на эталон
[error.409.modified.json](../api/error.409.modified.json).
