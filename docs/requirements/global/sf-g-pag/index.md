## SF-G-PAG. Пагинация {#sf-g-pag .collapsed}

- **Статус**: анализ
- **Приоритет**: must
- **Стабильность**: высокая — поведение снято со скриншотов и совпадает с дизайн-системой; открыто правило
  сокращения длинного ряда страниц (`UI-G-PAG-001.H01`)
- **Права доступа**: определяет операция списка, которая подключает функциональность
- **Использует**: [AR-001][], [дизайн-система][design-system] (Pagination, Select)
- **Используется в**: [SF-PT-LIST][]
- **Описание**: Единые правила постраничного просмотра списков: параметры запроса и ответ API, панель пагинации в
футере таблицы и сохранение условий списка при переходе между страницами.
- **Границы**:
    - **Входит**: Параметры `page` и `page_size`, конверт ответа со счётчиком `total`, страница за пределами списка,
      панель пагинации, состояние списка в адресе экрана.
    - **Не входит**: Порядок записей ([SF-G-SORT][]), поиск ([SF-G-SEARCH][]), фильтры ([SF-G-FILTER][]); курсорная
      и бесконечная прокрутка — не используются.

### Состав требований {#sf-g-pag-content .collapsed}

| Требование | Что описывает |
| :--- | :--- |
| [FR-G-PAG-001][] | Постраничная выдача списка (API) |
| [UI-G-PAG-001][] | Панель пагинации |

### Как подключить {#sf-g-pag-usage .collapsed}

Функциональность, которая подключает пагинацию, указывает в своих требованиях только:

- приставку `data-testid` экрана (например, `pt`), из которой строятся атрибуты элементов панели;
- порядок записей по умолчанию — через [SF-G-SORT][];
- показатели времени ответа для своего объёма данных.
