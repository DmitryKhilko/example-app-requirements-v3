# ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ {#fr}

Критерии приёмки опираются на [тестовый набор][fixture] `PT.fixture.json` уровня основной функциональности. Запросы
изменения статуса — запросы [AR-PT-UPDATE-001][], в которых меняется только `is_active`.

## FR-PT-ACTIVATION-001. Смена статуса записи вида изделий {#fr-pt-activation-001 .collapsed}

- **Использует**: [SF-PT-ACTIVATION][], [DR-PT-UPDATE-001][], [AR-PT-UPDATE-001][]
- **Используется в**: [FR-PT-UPDATE-001][], [FR-PT-ACTIVATION-002][]
- **Описание**: Система меняет статус записи справочника видов изделий: «Действует» (`is_active` = `true`) или «Не
действует» (`is_active` = `false`).
- **Условие**: Выполнено условие [FR-PT-UPDATE-001][]; значение `is_active` в запросе отличается от текущего (отказы —
в [FR-PT-UPDATE-002][]).
- **Результат**:
    - Система сохраняет новый статус, записывает в `updated_at` дату и время изменения и записывает в журнал аудита
      смену статуса: прежнее и новое значение (операция `STATUS_CHANGE` или `UPDATE`, [FR-PT-002][]).
    - Деактивация разрешена и для записи, которая используется в других сущностях: ссылки на неё сохраняются.
    - Недействующая запись:
        - остаётся в справочнике и в списке ([SF-PT-LIST][]) с бейджем «НЕ ДЕЙСТВУЕТ»;
        - не предлагается для выбора в новых документах других подсистем: они запрашивают список с фильтром
          `is_active` = `true` (см. `H01`);
        - показывается в уже созданных документах, которые на неё ссылаются;
        - может быть изменена и удалена по общим правилам ([SF-PT-UPDATE][], [SF-PT-DELETE][]).
    - Активация возвращает запись в выбор для новых документов.
    - Повторная установка того же статуса не меняет запись ([FR-PT-UPDATE-001][]).

### Критерии приёмки (AC) {#fr-pt-activation-001-ac .collapsed}

```gherkin
# language: ru
@FR-PT-ACTIVATION-001 @AR-PT-UPDATE-001
Функционал: Смена статуса записи вида изделий

  Предыстория:
    Дано в справочнике записи из файла "PT.fixture.json"
    И аутентифицированный пользователь с ролью "ais"

  Сценарий: Деактивация
    Когда он отправляет запрос изменения записи "Зажимы для галстуков" с текущими значениями,
      где "is_active" равно false
    Тогда код ответа равен 200
    И в теле ответа "is_active" равно false и "updated_at" позже "2026-11-23T08:36:44Z"
    И в журнале аудита есть запись о смене статуса записи "Зажимы для галстуков" с true на false

  Сценарий: Недействующая запись остаётся в списке и не попадает в выбор
    Дано запись "Зажимы для галстуков" деактивирована
    Когда он запрашивает список с параметром "search" = "зажимы"
    Тогда "items" содержит запись "Зажимы для галстуков" с "is_active" = false
    Когда он запрашивает список с параметрами "search" = "зажимы", "is_active" = true
    Тогда "items" пустой

  Сценарий: Активация
    Когда он отправляет запрос изменения записи "Брелоки" с текущими значениями, где "is_active" равно true
    Тогда код ответа равен 200
    И в теле ответа "is_active" равно true

  Сценарий: Повторная установка того же статуса
    Когда он отправляет запрос изменения записи "Брелоки" с текущими значениями
    Тогда код ответа равен 200
    И в теле ответа "updated_at" равно "2026-11-23T09:39:38Z"

  @manual
  Сценарий: Деактивация используемой записи
    Дано на запись "Броши" ссылается запись другой сущности
    Когда он отправляет запрос изменения записи "Броши" с текущими значениями, где "is_active" равно false
    Тогда код ответа равен 200
    И ссылка другой сущности на запись "Броши" сохранилась

  Сценарий: Роль без права изменения не может сменить статус
    Дано аутентифицированный пользователь с ролью "pko"
    Когда он отправляет запрос изменения записи "Брелоки", где "is_active" равно true
    Тогда код ответа равен 403
    И запись "Брелоки" по-прежнему имеет "is_active" = false
```

### Допущения {#fr-pt-activation-001-assumptions .collapsed}

- **FR-PT-ACTIVATION-001.H01**
    - **Статус**: требует подтверждения
    - **Подтверждает**: владелец справочника
    - **Допущение**: Документов, которые выбирают вид изделий, пока нет; правило «не предлагать недействующие записи»
      должны выполнять формы этих документов, запрашивая список с фильтром `is_active` = `true`.

## FR-PT-ACTIVATION-002. Смена статуса в форме изменения {#fr-pt-activation-002 .collapsed}

- **Использует**: [SF-PT-ACTIVATION][], [UI-PT-001][], [FR-PT-UPDATE-003][], [FR-PT-ACTIVATION-001][],
[FR-PT-LIST-005][]
- **Используется в**: [UC-PT-008][]
- **Описание**: Пользователь меняет статус записи переключателем «Действует» в форме изменения и видит новый статус
в списке.
- **Условие**: Открыта форма изменения записи ([FR-PT-UPDATE-003][]), у пользователя роль `ais`.
- **Результат**: После сохранения у записи в списке бейдж нового статуса, уведомление «Готово · Изделие сохранено.».

### Поведение {#fr-pt-activation-002-ux .collapsed}

- **Переключатель** — `pt-form-is-active` ([UI-PT-001][]): при открытии формы отражает текущий статус записи.
- Смена только статуса — тоже изменение: «Сохранить» отправляет запрос [AR-PT-UPDATE-001][] с новым `is_active` и
  прежними значениями остальных полей.
- После ответа `200` в строке записи бейдж `pt-list-status-badge` меняется на «ДЕЙСТВУЕТ» или «НЕ ДЕЙСТВУЕТ», а
  «Изменено» — на время сохранения. Если в списке применён фильтр по статусу, запись после смены статуса исчезает
  из текущей выборки.
- Отдельного подтверждения деактивации нет: действие обратимо (см. `H01`).

### Критерии приёмки (AC) {#fr-pt-activation-002-ac .collapsed}

```gherkin
# language: ru
@FR-PT-ACTIVATION-002 @UC-PT-008 @ui
Функционал: Смена статуса в форме изменения

  Предыстория:
    Дано в справочнике записи из файла "PT.fixture.json"
    И пользователь с ролью "ais" открыл экран "Виды изделий"

  Сценарий: Деактивация записи
    Дано открыта форма изменения записи "Броши"
    Когда пользователь выключает "pt-form-is-active" и нажимает "pt-form-submit"
    Тогда в теле запроса изменения "is_active" равно false, остальные поля не изменились
    И виден "toast" с заголовком "Готово" и текстом "Изделие сохранено."
    И в строке "Броши" "pt-list-status-badge" имеет data-value "false" и текст "НЕ ДЕЙСТВУЕТ"

  Сценарий: Активация записи
    Дано открыта форма изменения записи "Брелоки"
    Тогда "pt-form-is-active" имеет aria-checked "false"
    Когда пользователь включает "pt-form-is-active" и нажимает "pt-form-submit"
    Тогда в строке "Брелоки" "pt-list-status-badge" имеет текст "ДЕЙСТВУЕТ"

  Сценарий: Запись выходит из выборки с фильтром по статусу
    Дано применён фильтр "Статус: Действует"
    И открыта форма изменения записи "Броши"
    Когда пользователь выключает "pt-form-is-active" и нажимает "pt-form-submit"
    Тогда в таблице нет строки "Броши"
    И "pt-pagination-summary" содержит текст "из 13"
```

### Допущения {#fr-pt-activation-002-assumptions .collapsed}

- **FR-PT-ACTIVATION-002.H01**
    - **Статус**: требует подтверждения
    - **Подтверждает**: владелец справочника
    - **Допущение**: Деактивация не требует отдельного подтверждения, потому что запись не теряется и её можно снова
      активировать.
