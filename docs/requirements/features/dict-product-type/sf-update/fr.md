# ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ {#fr}

Критерии приёмки опираются на [тестовый набор][fixture] `PT.fixture.json` уровня основной функциональности. В примерах
изменяется запись «Зажимы для галстуков» (`pk` = `00000000-0000-4000-8000-000000000007`, `updated_at` =
`2026-11-23T08:36:44Z`).

## FR-PT-UPDATE-001. Изменение записи вида изделий {#fr-pt-update-001 .collapsed}

- **Использует**: [SF-PT-UPDATE][], [DR-PT-UPDATE-001][]
- **Используется в**: [AR-PT-UPDATE-001][], [FR-PT-UPDATE-003][], [FR-PT-ACTIVATION-001][]
- **Описание**: Система заменяет изменяемые поля записи справочника видов изделий значениями из запроса.
- **Условие**: Пользователь аутентифицирован и имеет право изменения (роль `ais`), запись существует, данные
соответствуют [DR-PT-UPDATE-001][], запись не изменена другим пользователем (отказы — в [FR-PT-UPDATE-002][]).
- **Результат**:
    - Система сохраняет значения полей запроса; `name_nominative` — без пробелов по краям.
    - Если хотя бы одно значение изменилось, система записывает в `updated_at` дату и время изменения (UTC) и
      записывает изменение в журнал аудита: прежние и новые значения изменённых полей ([FR-PT-002][]).
    - Если значения не изменились, запись, `updated_at` и журнал аудита остаются прежними.
    - `pk` и `created_at` не меняются.
    - Изменение статуса (`is_active`) подчиняется правилам [FR-PT-ACTIVATION-001][].
    - Система возвращает запись после изменения и код ответа `200`.
- **Показатели (NFR)**: Время ответа: 95-й процентиль — не более 500 мс при 10 000 записях в справочнике и 1000
последовательных запросов на тестовом стенде. Изменение записи и запись в журнал аудита выполняются в одной
транзакции: при сбое не сохраняется ни то, ни другое.

### Эталоны запроса и ответа {#fr-pt-update-001-examples .collapsed}

Запрос `PUT /api/v1/product-types/00000000-0000-4000-8000-000000000007`:

```json
--8<-- "requirements/features/dict-product-type/sf-update/api/AR-PT-UPDATE-001.request.json"
```

Ответ `200 OK` (значение `updated_at` — время изменения):

```json
--8<-- "requirements/features/dict-product-type/sf-update/api/AR-PT-UPDATE-001.response.200.json"
```

## FR-PT-UPDATE-002. Отказ в изменении записи вида изделий {#fr-pt-update-002 .collapsed}

- **Использует**: [SF-PT-UPDATE][], [DR-PT-UPDATE-001][]
- **Используется в**: [AR-PT-UPDATE-001][], [FR-PT-UPDATE-003][], [UI-PT-001][]
- **Описание**: Система отклоняет изменение записи, если пользователь не аутентифицирован или не имеет права
изменения, данные некорректны, записи нет, её изменил другой пользователь, такая запись уже существует либо
произошла внутренняя ошибка. При любом отказе запись не меняется и в журнал аудита ничего не записывается.
- **Порядок проверок**:
    1. Аутентификация: при отказе код ответа `401`.
    2. Право изменения: при отказе код ответа `403`.
    3. Формат `pk` и данные запроса: при отказе код ответа `400`, в ответе перечислены все найденные ошибки.
    4. Существование записи: при отказе код ответа `404`.
    5. Версия записи (`updated_at`) по [FR-G-LOCK-001][]: при отказе код ответа `409` с кодом `RECORD_MODIFIED`.
    6. Уникальность: при отказе код ответа `409` с кодом `DUPLICATE_PRODUCT_TYPE`.
- **Показатели (NFR)**: Текст `message` не содержит технических подробностей (стека, SQL, имён таблиц).

### Проверки данных {#fr-pt-update-002-checks .collapsed}

Поля записи проверяются по единому перечню [FR-PT-001][]. Дополнительные проверки изменения:

| Поле | Проверка | Код ошибки в `details` |
| :--- | :--- | :--- |
| `pk` (путь) | Значение — UUID | `INVALID_FORMAT` |
| `is_active` | Поле передано | `REQUIRED` |
| `is_active` | Значение — `true` или `false` | `INVALID_TYPE` |
| `updated_at` | Поле передано | `REQUIRED` |
| `updated_at` | Дата и время ISO 8601 в UTC | `INVALID_FORMAT` |
| Поле вне состава запроса (например, `pk`, `created_at`) | Поле не передаётся | `UNKNOWN_FIELD` |

### Коды ответов при отказе {#fr-pt-update-002-responses .collapsed}

| Код ответа | Код ошибки `code` | Когда |
| :--- | :--- | :--- |
| `400` | `VALIDATION_ERROR` | Одна или несколько проверок данных не пройдены |
| `401` | `UNAUTHORIZED` | Пользователь не аутентифицирован |
| `403` | `FORBIDDEN` | У пользователя нет права изменения |
| `404` | `NOT_FOUND` | Записи с таким `pk` нет |
| `409` | `RECORD_MODIFIED` | `updated_at` не совпадает с текущим |
| `409` | `DUPLICATE_PRODUCT_TYPE` | Другая запись с таким наименованием и типом |
| `500` | `INTERNAL_ERROR` | Внутренняя ошибка: запись не меняется |

### Эталоны отказов {#fr-pt-update-002-examples .collapsed}

Запрос с ошибками: пустое наименование, недопустимый статус, нет `updated_at`, лишнее поле `pk`.

```json
--8<-- "requirements/features/dict-product-type/sf-update/api/AR-PT-UPDATE-001.request.invalid.json"
```

Ответ `400 Bad Request`:

```json
--8<-- "requirements/features/dict-product-type/sf-update/api/AR-PT-UPDATE-001.response.400.json"
```

Запрос с устаревшим `updated_at` (файл `AR-PT-UPDATE-001.request.stale.json`), ответ `409 Conflict` — общий эталон
[FR-G-LOCK-001][]:

```json
--8<-- "requirements/global/api/error.409.modified.json"
```

Переименование в «Броши» той же группы (файл `AR-PT-UPDATE-001.request.duplicate.json`), ответ `409 Conflict`:

```json
--8<-- "requirements/features/dict-product-type/sf-update/api/AR-PT-UPDATE-001.response.409.duplicate.json"
```

## FR-PT-UPDATE-003. Форма изменения вида изделий {#fr-pt-update-003 .collapsed}

- **Использует**: [SF-PT-UPDATE][], [UI-PT-001][], [DR-PT-UPDATE-001][], [FR-PT-UPDATE-001][],
[FR-PT-UPDATE-002][], [AR-PT-UPDATE-001][], [AR-PT-READ-001][], [FR-PT-LIST-005][], [UI-G-LOCK-001][],
[UI-G-TOAST-001][]
- **Используется в**: [UC-PT-007][], [UC-PT-008][]
- **Описание**: Система открывает форму [UI-PT-001][] в режиме изменения с актуальными данными записи, отправляет
изменения и сообщает результат. Поля, проверки, кнопки и общее поведение формы описаны в [UI-PT-001][]; здесь —
только особенности изменения.
- **Условие**: Открыт экран списка ([FR-PT-LIST-005][]), у пользователя роль `ais`. Для остальных ролей клик по строке
окно не открывает.
- **Результат**: После успешного сохранения окно закрывается, пользователь видит уведомление «Готово · Изделие
сохранено.», список перезагружается с текущими условиями и показывает изменённую запись.
- **Показатели (NFR)**: Окно открывается не позже 100 мс после клика по строке; поля заполняются данными не позже
1 с при ответе [AR-PT-READ-001][] в пределах его показателя.

### Особенности режима изменения {#fr-pt-update-003-mode .collapsed}

- **Открытие**: клик по строке списка вне флажка или Enter на строке (`pt-list-row`, [FR-PT-LIST-005][]); окно
  `pt-form-modal` с `data-mode="update"` и `data-pk` записи, заголовок «Изменить изделие».
- **Загрузка данных**: окно сразу запрашивает запись операцией `GET /api/v1/product-types/{pk}` ([AR-PT-READ-001][]).
  Пока ответа нет, вместо полей показывается скелетон `pt-form-loading`, кнопка «Сохранить» недоступна.
- **Значения при открытии**: все поля, включая переключатель «Действует», заполнены данными записи из ответа;
  наименование в фокусе. Значение `updated_at` из ответа форма хранит для запроса изменения.
- **Запись не найдена при открытии** (ответ `404`): окно закрывается, уведомление «Ошибка» с текстом «Запись не
  найдена. Возможно, её удалил другой пользователь.», список перезагружается.
- **Нет изменений**: если при нажатии «Сохранить» значения совпадают со значениями при открытии, окно закрывается
  без запроса и без уведомления.
- **Запрос**: `PUT /api/v1/product-types/{pk}` ([AR-PT-UPDATE-001][]) со всеми полями формы и сохранённым
  `updated_at`.
- **Ответы**, кроме общих из [UI-PT-001][]:
    - `200`: окно закрывается, фокус возвращается на строку, уведомление «Готово» с текстом «Изделие сохранено.»,
      список перезагружается.
    - `409` `RECORD_MODIFIED`: по [UI-G-LOCK-001][] — уведомление «Ошибка», окно остаётся открытым, введённые
      данные сохраняются.
    - `404`: окно закрывается, уведомление «Ошибка» с текстом «Запись не найдена. Возможно, её удалил другой
      пользователь.», список перезагружается.

После перезагрузки списка изменённая запись остаётся там, куда её помещают условия списка: при сортировке по
изменённому полю она может перейти на другую страницу.

## AR-PT-UPDATE-001. Изменение вида изделий (API) {#ar-pt-update-001 .collapsed}

- **Использует**: [AR-PT-001][], [FR-PT-UPDATE-001][], [FR-PT-UPDATE-002][], [DR-PT-UPDATE-001][],
[FR-PT-ACTIVATION-001][]
- **Метод и путь**: `PUT /api/v1/product-types/{pk}`
- **Права доступа**: роль `ais` (см. [SF-PT-UPDATE][])
- **Заголовок запроса**: `Content-Type: application/json`
- **Параметры**: `pk` в пути — идентификатор записи (UUID); тело — все изменяемые поля и `updated_at`.
- **Форматы**: Тело запроса и ответа — JSON в кодировке UTF-8; количества — JSON-числа; дата и время — ISO 8601 в UTC.

### Ответы {#ar-pt-update-001-responses .collapsed}

| Код ответа | Когда | Тело |
| :--- | :--- | :--- |
| `200` | Запись изменена или не требовала изменений | Запись после изменения |
| `400` | Ошибки в данных запроса | Ошибка с перечнем по полям |
| `401` | Пользователь не аутентифицирован | Ошибка |
| `403` | Нет права изменения | Ошибка |
| `404` | Записи нет | Ошибка |
| `409` | Запись изменена другим пользователем | Ошибка |
| `409` | Запись с таким наименованием и типом уже есть | Ошибка с полем |
| `500` | Внутренняя ошибка | Ошибка |

Тела ответов с ошибками соответствуют общей схеме
[error.response.schema.json](../../../global/api/error.response.schema.json).

### Файлы эталонов и схем {#ar-pt-update-001-files .collapsed}

| Файл | Назначение |

| `AR-PT-UPDATE-001.request.schema.json` | Схема тела запроса |
