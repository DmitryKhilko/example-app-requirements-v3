# ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ {#fr}

## FR-PT-CREATE-001. Создание записи вида изделий {#fr-pt-create-001 .collapsed}

- **Использует**: [SF-PT-CREATE][], [DR-PT-CREATE-001][]
- **Используется в**: [AR-PT-CREATE-001][]
- **Описание**: Система создаёт запись справочника видов изделий, если пользователь с правом создания передал корректные
данные.
- **Условие**: Пользователь аутентифицирован и имеет право создания (роль `ais`), данные запроса соответствуют
[DR-PT-CREATE-001][] (проверки описаны в [FR-PT-CREATE-002][]).
- **Результат**:
    - Система создаёт запись с новым идентификатором `pk`.
    - Система сохраняет значения полей запроса, при этом `name_nominative` сохраняется без пробелов по краям.
    - Система сохраняет `is_active` из запроса; если поле не передано или равно `null`, устанавливает `true`.
    - Система записывает дату и время создания (UTC) в `created_at`, а в `updated_at` записывает то же значение (см.
      `H01`).
    - Система записывает создание в журнал аудита (операция `CREATE`, [FR-PT-002][]).
    - Система возвращает созданную запись и код ответа `201`.
- **Показатели (NFR)**: Время ответа: 95-й процентиль — не более 500 мс при 10 000 записях в справочнике и 1000
последовательных запросов создания по условиям [NFR-001][]. Создание записи и запись в журнал аудита выполняются в
одной транзакции.

### Эталоны запроса и ответа {#fr-pt-create-001-examples .collapsed}

Запрос `POST /api/v1/product-types`:

```json
--8<-- "requirements/features/dict-product-type/sf-create/api/AR-PT-CREATE-001.request.json"
```

Ответ `201 Created`:

```json
--8<-- "requirements/features/dict-product-type/sf-create/api/AR-PT-CREATE-001.response.201.json"
```

### Критерии приёмки (AC) {#fr-pt-create-001-ac .collapsed}

```gherkin

@FR-PT-CREATE-001 @AR-PT-CREATE-001
Функционал: Создание записи вида изделий

  Сценарий: Успешное создание записи
    Дано аутентифицированный пользователь с ролью "ais"
    Когда он отправляет запрос с телом из файла "AR-PT-CREATE-001.request.json"
    Тогда код ответа равен 201
    И тело ответа соответствует схеме "AR-PT-001.product-type.schema.json"
    И в теле ответа "is_active" равно true
    И в теле ответа "updated_at" равно "created_at"

  Сценарий: Создание недействующей записи
    Дано аутентифицированный пользователь с ролью "ais"
    Когда он отправляет запрос с телом из файла "AR-PT-CREATE-001.request.json",
      где "is_active" равно false
    Тогда код ответа равен 201
    И в теле ответа "is_active" равно false

  Сценарий: Пробелы по краям наименования обрезаются
    Дано аутентифицированный пользователь с ролью "ais"
    Когда он отправляет запрос с телом из файла "AR-PT-CREATE-001.request.json",
      где "name_nominative" равно "  Кольцо  "
    Тогда код ответа равен 201
    И в теле ответа "name_nominative" равно "Кольцо"

  @NFR @performance
  Сценарий: Время ответа
    Дано в справочнике 10 000 записей
    Когда он отправляет 1000 последовательных запросов создания записей с разными наименованиями
    Тогда 95-й процентиль времени ответа не больше 500 мс
```

### Допущения {#fr-pt-create-001-assumptions .collapsed}

- **FR-PT-CREATE-001.H01**
    - **Статус**: принято
    - **Подтверждает**: владелец справочника
    - **Допущение**: При создании записи `updated_at` равно `created_at`, а не пустое, потому что поле обязательно.

## FR-PT-CREATE-002. Отказ в создании записи вида изделий {#fr-pt-create-002 .collapsed}

- **Использует**: [SF-PT-CREATE][], [DR-PT-CREATE-001][]
- **Используется в**: [AR-PT-CREATE-001][]
- **Описание**: Система отклоняет создание записи, если пользователь не аутентифицирован или не имеет права создания,
данные некорректны, такая запись уже существует либо произошла внутренняя ошибка. При любом отказе запись не создаётся и
в журнал аудита ничего не записывается.
- **Порядок проверок**:
    1. Аутентификация: при отказе код ответа `401`.
    2. Право создания: при отказе код ответа `403`.
    3. Состав и формат данных: при отказе код ответа `400`, в ответе перечислены все найденные ошибки, а не
       только первая.
    4. Уникальность наименования в типе изделия ([DR-PT-001][]): при отказе код ответа `409`.

### Проверки данных {#fr-pt-create-002-checks .collapsed}

Поля записи проверяются по единому перечню [FR-PT-001][]; `is_active` при создании необязательно. Поле вне состава
запроса (например, `pk`, `created_at`, `updated_at`) даёт ошибку `UNKNOWN_FIELD` по общим правилам [AR-001][].

### Коды ответов при отказе {#fr-pt-create-002-responses .collapsed}

| Код ответа | Код ошибки `code` | Когда |
| :--- | :--- | :--- |
| `400` | `VALIDATION_ERROR` | Одна или несколько проверок данных не пройдены |
| `401` | `UNAUTHORIZED` | Пользователь не аутентифицирован |
| `403` | `FORBIDDEN` | У пользователя нет права создания |
| `409` | `DUPLICATE_PRODUCT_TYPE` | Запись с таким наименованием в этой группе уже существует |
| `500` | `INTERNAL_ERROR` | Внутренняя ошибка: запись не создаётся |

### Эталоны отказов {#fr-pt-create-002-examples .collapsed}

#### 400. Ошибки в данных запроса {#fr-pt-create-002-examples-400 .collapsed}

Запрос нарушает сразу несколько проверок: пустое наименование, недопустимая группа, нечисловое значение, значение вне
диапазона, отсутствующее обязательное поле и лишнее поле.

Запрос:

```json
--8<-- "requirements/features/dict-product-type/sf-create/api/AR-PT-CREATE-001.request.invalid.json"
```

Ответ `400 Bad Request`:

```json
--8<-- "requirements/features/dict-product-type/sf-create/api/AR-PT-CREATE-001.response.400.json"
```

#### 401. Пользователь не аутентифицирован {#fr-pt-create-002-examples-401 .collapsed}

Корректный запрос из файла `AR-PT-CREATE-001.request.json` отправлен без действительных данных аутентификации.

Запрос:

```json
--8<-- "requirements/features/dict-product-type/sf-create/api/AR-PT-CREATE-001.request.json"
```

Ответ `401 Unauthorized`:

```json
--8<-- "requirements/features/global/api/error.401.json"
```

#### 403. Нет права создания {#fr-pt-create-002-examples-403 .collapsed}

Корректный запрос из файла `AR-PT-CREATE-001.request.json` отправлен пользователем с ролью, которой создание
запрещено (например, `pko`).

Запрос:

```json
--8<-- "requirements/features/dict-product-type/sf-create/api/AR-PT-CREATE-001.request.json"
```

Ответ `403 Forbidden`:

```json
--8<-- "requirements/features/global/api/error.403.json"
```

#### 409. Запись уже существует {#fr-pt-create-002-examples-409 .collapsed}

Корректный запрос из файла `AR-PT-CREATE-001.request.json` отправлен, когда в группе `JEWELRY` уже есть вид
изделий «Кольцо».

Запрос:

```json
--8<-- "requirements/features/dict-product-type/sf-create/api/AR-PT-CREATE-001.request.json"
```

Ответ `409 Conflict`:

```json
--8<-- "requirements/features/dict-product-type/sf-create/api/AR-PT-CREATE-001.response.409.json"
```

#### 500. Внутренняя ошибка {#fr-pt-create-002-examples-500 .collapsed}

Корректный запрос из файла `AR-PT-CREATE-001.request.json` вызывает сбой при обработке. Запись не создаётся.

Ответ `500 Internal Server Error`:

```json
--8<-- "requirements/features/global/api/error.500.json"
```

```gherkin

    Дано аутентифицированный пользователь с ролью "ais"
    Когда он отправляет запрос с телом из файла "AR-PT-CREATE-001.request.invalid.json"
    Тогда код ответа равен 400
    И тело ответа равно содержимому файла "AR-PT-CREATE-001.response.400.json"
    И запись не создана

    Дано в группе "JEWELRY" есть вид изделий "Кольцо"

    Когда он отправляет запрос с телом из файла "AR-PT-CREATE-001.request.json"
```

## FR-PT-CREATE-003. Форма создания вида изделий {#fr-pt-create-003 .collapsed}

- **Использует**: [SF-PT-CREATE][], [UI-PT-001][], [DR-PT-CREATE-001][], [FR-PT-CREATE-001][],
[FR-PT-CREATE-002][], [AR-PT-CREATE-001][], [FR-PT-LIST-005][], [SF-G-TOAST][]
- **Используется в**: [UC-PT-006][]
- **Описание**: Система открывает форму [UI-PT-001][] в режиме создания, отправляет данные на создание и сообщает
результат. Поля, проверки, кнопки и общее поведение формы описаны в [UI-PT-001][]; здесь — только особенности
создания.
- **Условие**: Открыт экран списка ([FR-PT-LIST-005][]), у пользователя роль `ais`. Для остальных ролей кнопка
«Добавить изделие» не выводится, окно открыть нельзя.
- **Результат**: После успешного сохранения окно закрывается, пользователь видит уведомление «Готово · Изделие
добавлено.», список перезагружается с текущими условиями и содержит новую запись с выбранным статусом.
- **Показатели (NFR)**: Окно открывается не позже 100 мс после нажатия «Добавить изделие», без запроса к API.

### Особенности режима создания {#fr-pt-create-003-mode .collapsed}

- **Открытие**: кнопка «Добавить изделие» (`pt-list-create-button`) экрана списка; окно `pt-form-modal` с
  `data-mode="create"`, заголовок «Добавить изделие».
- **Значения при открытии**: наименование и тип не заполнены; базовое количество натиров — 0,5; количество натиров
  для золотых изделий оптовой торговли — 0,5; количество наложенных оттисков — 1; переключатель «Действует» включён.
  Данные прошлого открытия не сохраняются.
- **Запрос**: `POST /api/v1/product-types` ([AR-PT-CREATE-001][]) с полями формы, включая `is_active`.
- **Ответ `201`**: окно закрывается, фокус возвращается на «Добавить изделие», уведомление «Готово» с текстом
  «Изделие добавлено.», список перезагружается. Новая запись видна там, куда её помещают условия списка: без
  сортировки — последней на последней странице.
- Остальные ответы — по таблице поведения [UI-PT-001][].

### Критерии приёмки (AC) {#fr-pt-create-003-ac .collapsed}

Общие проверки формы (ошибки полей, стрелки, закрытие, доступность) — в [UI-PT-001][].

```gherkin
# language: ru
@FR-PT-CREATE-003 @UC-PT-006 @ui
Функционал: Форма создания вида изделий

  Предыстория:
    Дано в справочнике записи из файла "PT.fixture.json"
    И пользователь с ролью "ais" открыл экран "Виды изделий"

  Сценарий: Открытие формы
    Когда пользователь нажимает "pt-list-create-button"
    Тогда виден "pt-form-modal" с data-mode "create"
    И "pt-form-title" содержит текст "Добавить изделие"
    И "pt-form-name" пустое и в фокусе
    И "pt-form-product-group" показывает плейсхолдер "Выберите тип"
    И "pt-form-default-streak-count" и "pt-form-wholesale-gold-streak-count" содержат "0,5"
    И "pt-form-stamp-impressions-count" содержит "1"
    И "pt-form-step-down" с data-field "default_streak_count" недоступна
    И "pt-form-is-active" включён (aria-checked "true") и подписан "Действует"

  Сценарий: Успешное создание
    Дано открыта форма создания
    Когда пользователь вводит "  Подвески  " в "pt-form-name"
    И выбирает "Ювелирные изделия" в "pt-form-product-group"
    И вводит "2" в "pt-form-default-streak-count"
    И нажимает "pt-form-submit"
    Тогда отправлен один запрос "POST /api/v1/product-types" с телом:
      """
      {"name_nominative": "Подвески", "product_group": "JEWELRY", "default_streak_count": 2,
       "wholesale_gold_streak_count": 0.5, "stamp_impressions_count": 1, "is_active": true}
      """
    И "pt-form-modal" закрыт и фокус на "pt-list-create-button"
    И виден "toast" с заголовком "Готово" и текстом "Изделие добавлено."
    И "pt-pagination-summary" содержит текст "Показано 1–10 из 16"
    И на странице 2 последняя строка — "Подвески" со статусом "ДЕЙСТВУЕТ"

  Сценарий: Создание недействующей записи
    Дано открыта форма создания
    Когда пользователь вводит "Подвески" в "pt-form-name"
    И выбирает "Ювелирные изделия" в "pt-form-product-group"
    И выключает "pt-form-is-active"
    И нажимает "pt-form-submit"
    Тогда в теле запроса создания "is_active" равно false
    И на странице 2 последняя строка — "Подвески" со статусом "НЕ ДЕЙСТВУЕТ"

  Сценарий: Повторное открытие начинается с пустой формы
    Дано пользователь ввёл "Подвески" в форме создания и нажал "pt-form-cancel"
    Когда пользователь нажимает "pt-list-create-button"
    Тогда "pt-form-name" пустое

  @NFR @performance
  Сценарий: Скорость открытия окна
    Когда пользователь нажимает "pt-list-create-button"
    Тогда "pt-form-modal" появляется не позже 100 мс после нажатия
```

## AR-PT-CREATE-001. Создание вида изделий (API) {#ar-pt-create-001 .collapsed}

- **Использует**: [AR-PT-001][], [FR-PT-CREATE-001][], [FR-PT-CREATE-002][], [DR-PT-CREATE-001][]
- **Метод и путь**: `POST /api/v1/product-types`
- **Права доступа**: роль `ais` (см. [SF-PT-CREATE][])
- **Заголовок запроса**: `Content-Type: application/json`
- **Форматы**: Тело запроса и ответа: JSON в кодировке UTF-8. Количества передаются JSON-числами. Идентификатор `pk` —
UUID. Дата и время — ISO 8601 в UTC, например `2026-11-20T09:30:15Z`.

### Ответы {#ar-pt-create-001-responses .collapsed}

| Код ответа | Когда | Тело | Эталон |
| :--- | :--- | :--- | :--- |
| `201` | Запись создана | Созданная запись | [файл](api/AR-PT-CREATE-001.response.201.json) |
| `400` | Ошибки в данных запроса | Ошибка с перечнем по полям | [файл](api/AR-PT-CREATE-001.response.400.json) |
| `401` | Пользователь не аутентифицирован | Ошибка | [error.401.json](../../global/api/error.401.json) |
| `403` | Нет права создания | Ошибка | [error.403.json](../../global/api/error.403.json) |
| `409` | Запись уже существует | Ошибка с указанием поля | [файл](api/AR-PT-CREATE-001.response.409.json) |
| `500` | Внутренняя ошибка | Ошибка | [error.500.json](../../global/api/error.500.json) |

Тела ответов с ошибками (`400`–`500`) соответствуют общей схеме
[error.response.schema.json](../../global/api/error.response.schema.json).

### Файлы эталонов и схем {#ar-pt-create-001-files .collapsed}

Файлы лежат в каталоге [api/](api/) рядом со страницей. Автотесты берут запросы, ответы и схемы из этих же файлов,
поэтому страница и тесты не расходятся.

| Файл | Назначение |
| :--- | :--- |
| `AR-PT-CREATE-001.request.schema.json` | Схема тела запроса |
| `AR-PT-CREATE-001.request.json` | Корректный запрос |
| `AR-PT-CREATE-001.request.invalid.json` | Запрос с ошибками (ответ `400`) |
| `AR-PT-001.product-type.schema.json` | Схема тела ответа `201`: общая схема записи ([AR-PT-001][]) |
| `AR-PT-CREATE-001.response.201.json` | Эталон ответа `201` |
| `AR-PT-CREATE-001.response.400.json` | Эталон ответа `400` |
| `AR-PT-CREATE-001.response.409.json` | Эталон ответа `409` |

Эталоны ответов `401`, `403` и `500` общие для всех операций и лежат в глобальном каталоге:
[error.401.json](../../global/api/error.401.json), [error.403.json](../../global/api/error.403.json),
[error.500.json](../../global/api/error.500.json) ([AR-001][]).
