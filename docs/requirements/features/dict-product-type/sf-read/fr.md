# ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ {#fr}

Критерии приёмки опираются на [тестовый набор][fixture] `PT.fixture.json` уровня основной функциональности.

## FR-PT-READ-001. Получение записи вида изделий {#fr-pt-read-001 .collapsed}

- **Использует**: [SF-PT-READ][], [DR-PT-LIST-001][]
- **Используется в**: [AR-PT-READ-001][], [FR-PT-UPDATE-003][]
- **Описание**: Система возвращает все поля записи справочника видов изделий по её идентификатору.
- **Условие**: Пользователь аутентифицирован, его роль разрешена в [SF-PT-READ][], запись с идентификатором `pk`
существует (отказы описаны в [FR-PT-READ-002][]).
- **Результат**:
    - Система возвращает запись со всеми полями [DR-PT-LIST-001][]: `pk`, `name_nominative`, `product_group`,
      `default_streak_count`, `wholesale_gold_streak_count`, `stamp_impressions_count`, `is_active`, `created_at`,
      `updated_at`.
    - Запись возвращается независимо от статуса: и действующая, и недействующая.
    - Значение `updated_at` из ответа клиент передаёт при изменении записи для проверки, что её не изменили другие
      пользователи ([DR-PT-UPDATE-001][]).
    - Система не изменяет данные и не записывает чтение в журнал аудита.
    - Код ответа `200`.
- **Показатели (NFR)**: Время ответа: 95-й процентиль — не более 200 мс при 10 000 записях в справочнике и 1000
последовательных запросов к случайным записям на тестовом стенде.

## FR-PT-READ-002. Отказ в получении записи вида изделий {#fr-pt-read-002 .collapsed}

- **Использует**: [SF-PT-READ][]
- **Используется в**: [AR-PT-READ-001][], [FR-PT-UPDATE-003][]
- **Описание**: Система отклоняет запрос записи, если пользователь не аутентифицирован или не имеет права просмотра,
идентификатор некорректен, записи нет либо произошла внутренняя ошибка.
- **Порядок проверок**:
    1. Аутентификация: при отказе код ответа `401`.
    2. Право просмотра: при отказе код ответа `403`.
    3. Формат идентификатора: `pk` — UUID; при отказе код ответа `400`, в `details` поле `pk` с кодом
       `INVALID_FORMAT`.
    4. Существование записи: при отказе код ответа `404`. Удалённая запись не существует ([SF-PT-DELETE][]).
- **Показатели (NFR)**: Текст `message` не содержит технических подробностей (стека, SQL, имён таблиц).

### Коды ответов при отказе {#fr-pt-read-002-responses .collapsed}

| Код ответа | Код ошибки `code` | Когда |
| :--- | :--- | :--- |
| `400` | `VALIDATION_ERROR` | `pk` не является UUID |
| `401` | `UNAUTHORIZED` | Пользователь не аутентифицирован |
| `403` | `FORBIDDEN` | У пользователя нет ни одной роли справочника |
| `404` | `NOT_FOUND` | Записи с таким `pk` нет |
| `500` | `INTERNAL_ERROR` | Внутренняя ошибка |

### Критерии приёмки (AC) {#fr-pt-read-002-ac .collapsed}

Отказы `401` и `500` проверяются общими сценариями [AR-001][] для всех операций.

```gherkin
# language: ru
@FR-PT-READ-002 @AR-PT-READ-001
Функционал: Отказ в получении записи вида изделий

  Предыстория:
    Дано в справочнике записи из файла "PT.fixture.json"

  Сценарий: Некорректный идентификатор
    Дано аутентифицированный пользователь с ролью "ais"
    Когда он отправляет запрос "GET /api/v1/product-types/abc"
    Тогда код ответа равен 400
    И тело ответа равно содержимому файла "AR-PT-READ-001.response.400.json"

  Сценарий: Записи нет
    Дано аутентифицированный пользователь с ролью "ais"
    Когда он отправляет запрос "GET /api/v1/product-types/00000000-0000-4000-8000-000000000999"
    Тогда код ответа равен 404
    И тело ответа равно содержимому файла "AR-PT-READ-001.response.404.json"

  Сценарий: Нет права просмотра
    Дано аутентифицированный пользователь без ролей справочника (например, пользователь другой подсистемы)
    Когда он отправляет запрос "GET /api/v1/product-types/3f2a9c1e-6b7d-4e58-9a10-2c4d6e8f0a11"
    Тогда код ответа равен 403
    И тело ответа равно содержимому файла "error.403.json"
```

## AR-PT-READ-001. Получение вида изделий (API) {#ar-pt-read-001 .collapsed}

- **Использует**: [AR-PT-001][], [FR-PT-READ-001][], [FR-PT-READ-002][], [DR-PT-LIST-001][]
- **Метод и путь**: `GET /api/v1/product-types/{pk}`
- **Права доступа**: роли из [SF-PT-READ][]
- **Параметры**: `pk` в пути — идентификатор записи (UUID). Строки запроса и тела у запроса нет.
- **Форматы**: Тело ответа — JSON в кодировке UTF-8; количества — JSON-числа; дата и время — ISO 8601 в UTC.

### Ответы {#ar-pt-read-001-responses .collapsed}

| Код ответа | Когда | Тело |
| :--- | :--- | :--- |
| `200` | Запись найдена | Запись со всеми полями |
| `400` | `pk` не является UUID | Ошибка с полем `pk` |
| `401` | Пользователь не аутентифицирован | Ошибка |
| `403` | Нет права просмотра | Ошибка |
| `404` | Записи нет | Ошибка |
| `500` | Внутренняя ошибка | Ошибка |

Тела ответов с ошибками соответствуют общей схеме
[error.response.schema.json](../../../global/api/error.response.schema.json).

### Файлы эталонов и схем {#ar-pt-read-001-files .collapsed}

Файлы лежат в каталоге [api/](api/) рядом со страницей.

| Файл | Назначение |
| :--- | :--- |
| `AR-PT-001.product-type.schema.json` | Схема тела ответа `200`: общая схема записи ([AR-PT-001][]) |
| `AR-PT-READ-001.response.200.json` | Эталон ответа `200` для записи «Кольца разные» тестового набора |
| `AR-PT-READ-001.response.400.json` | Эталон ответа `400` |
| `AR-PT-READ-001.response.404.json` | Эталон ответа `404` |

Эталоны ответов `401`, `403` и `500` общие для всех операций и лежат в глобальном каталоге:
[error.401.json](../../../global/api/error.401.json), [error.403.json](../../../global/api/error.403.json),
[error.500.json](../../../global/api/error.500.json) ([AR-001][]).
