# ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ {#fr}

Требования `FR-PT-LIST-001`–`004` и `009` описывают поведение системы через API, `FR-PT-LIST-005`–`008` — экран списка
(упрощение UI по стандарту: экран одной SF описывается внутри её FR). Нефункциональные требования встроены в FR
показателями и проверяются сценариями с тегом `@NFR`.

Список подключает глобальные функциональности: пагинацию [SF-G-PAG][], сортировку [SF-G-SORT][], поиск
[SF-G-SEARCH][], фильтрацию [SF-G-FILTER][] и уведомления [SF-G-TOAST][]. Их общие правила, элементы экрана и
критерии приёмки здесь не повторяются; требования ниже задают только то, что относится к справочнику видов изделий:
поля, порядок по умолчанию, правила сравнения, перечень фильтров, тексты и сценарии на данных справочника.

Критерии приёмки опираются на [тестовый набор][fixture] уровня основной функциональности.

## FR-PT-LIST-001. Получение страницы списка видов изделий {#fr-pt-list-001 .collapsed}

- **Использует**: [SF-PT-LIST][], [DR-PT-LIST-001][], [FR-G-PAG-001][]
- **Используется в**: [AR-PT-LIST-001][], [FR-PT-LIST-005][]
- **Описание**: Система возвращает страницу записей справочника видов изделий и общее количество записей, которые
удовлетворяют условиям запроса, по правилам пагинации [FR-G-PAG-001][].
- **Условие**: Пользователь аутентифицирован, его роль разрешена в [SF-PT-LIST][], параметры запроса корректны
(проверки описаны в [FR-PT-LIST-004][]).
- **Результат**:
    - Страница, её размер, `total` и ответ на страницу за пределами списка — по [FR-G-PAG-001][].
    - Без сортировки записи упорядочены по `created_at`, затем по `pk`, по возрастанию ([FR-PT-LIST-003][]).
    - Каждая запись содержит все поля [DR-PT-LIST-001][] в представлении [AR-PT-001][].
    - Записи со статусом «Не действует» входят в список наравне с действующими, если не задан фильтр `is_active`.
    - Система не изменяет данные и не записывает чтение списка в журнал аудита (см. `H01`).
- **Показатели (NFR)**: Время ответа: 95-й процентиль — не более 500 мс, максимум — не более 1000 мс при 10 000
записях, любой допустимой комбинации параметров и 1000 последовательных запросов по условиям [NFR-001][].

### Эталоны запроса и ответа {#fr-pt-list-001-examples .collapsed}

Запрос `GET /api/v1/product-types` с параметрами (ювелирные изделия, созданные 18–19.11.2026 по UTC+3, по возрастанию
даты создания):

```json
--8<-- "requirements/features/dict-product-type/sf-list/api/AR-PT-LIST-001.request.json"
```

Ответ `200 OK`:

```json
--8<-- "requirements/features/dict-product-type/sf-list/api/AR-PT-LIST-001.response.200.json"
```

### Критерии приёмки (AC) {#fr-pt-list-001-ac .collapsed}

Постраничная выдача (страницы, размер, страница за пределами списка, пустой список) проверяется сценариями
[FR-G-PAG-001][] на этом справочнике.

```gherkin
# language: ru
@FR-PT-LIST-001 @AR-PT-LIST-001
Функционал: Получение страницы списка видов изделий

  Предыстория:
    Дано в справочнике записи из файла "PT.fixture.json"
    И аутентифицированный пользователь с ролью "ais"

  Сценарий: Первая страница по умолчанию
    Когда он запрашивает список без параметров
    Тогда код ответа равен 200
    И тело ответа соответствует схеме "AR-PT-LIST-001.response.200.schema.json"
    И "items" содержит 10 записей, первая — "Кольца разные", последняя — "Кольца обручальные"

  Сценарий: Неактивные записи входят в список
    Когда он запрашивает список с параметром "page_size" = 25
    Тогда "items" содержит запись "Брелоки" с "is_active" = false

  Сценарий: Пустой справочник
    Дано справочник пуст
    Когда он запрашивает список без параметров
    Тогда тело ответа равно содержимому файла "AR-PT-LIST-001.response.200.empty.json"

  Сценарий: Просмотр доступен ролям без права изменения
    Дано аутентифицированный пользователь с ролью "pko"
    Когда он запрашивает список без параметров
    Тогда код ответа равен 200

  Сценарий: Чтение не меняет данные и не пишется в журнал аудита
    Когда он запрашивает список без параметров
    Тогда записи справочника не изменились
    И в журнале аудита не появилось новых записей

  @NFR @performance
  Сценарий: Время ответа при 10 000 записях
    Дано в справочнике 10 000 записей
    Когда он отправляет 1000 последовательных запросов списка со случайной допустимой комбинацией параметров
    Тогда 95-й процентиль времени ответа не больше 500 мс
    И максимальное время ответа не больше 1000 мс
```

### Допущения {#fr-pt-list-001-assumptions .collapsed}

- **FR-PT-LIST-001.H01**
    - **Статус**: требует подтверждения
    - **Подтверждает**: владелец справочника
    - **Допущение**: Просмотр списка не записывается в журнал аудита: аудит в [F-PT][] касается изменений записей.

## FR-PT-LIST-002. Поиск видов изделий по наименованию {#fr-pt-list-002 .collapsed}

- **Использует**: [SF-PT-LIST][], [DR-PT-LIST-001][], [FR-G-SEARCH-001][]
- **Используется в**: [AR-PT-LIST-001][], [FR-PT-LIST-006][]
- **Описание**: Система ищет записи справочника по вхождению строки в наименование по правилам поиска
[FR-G-SEARCH-001][].
- **Условие**: Выполнено условие [FR-PT-LIST-001][]; передан параметр `search`.
- **Результат**:
    - Поиск идёт только по полю `name_nominative`; тип изделия, количества и статус в поиске не участвуют.
    - Максимальная длина строки — 150 символов, как у наименования ([DR-PT-001][]).
    - Обрезка пробелов, регистр, служебные символы, пустой результат и сочетание с фильтрами — по
      [FR-G-SEARCH-001][].
- **Показатели (NFR)**: Время ответа с поиском — по показателю [FR-PT-LIST-001][].

### Эталоны {#fr-pt-list-002-examples .collapsed}

Ничего не найдено:

```json
--8<-- "requirements/features/dict-product-type/sf-list/api/AR-PT-LIST-001.request.not-found.json"
```

Ответ `200 OK`:

```json
--8<-- "requirements/features/dict-product-type/sf-list/api/AR-PT-LIST-001.response.200.empty.json"
```

### Критерии приёмки (AC) {#fr-pt-list-002-ac .collapsed}

Общие правила сравнения проверяются сценариями [FR-G-SEARCH-001][] на этом справочнике.

```gherkin
# language: ru
@FR-PT-LIST-002 @AR-PT-LIST-001
Функционал: Поиск видов изделий по наименованию

  Предыстория:
    Дано в справочнике записи из файла "PT.fixture.json"
    И аутентифицированный пользователь с ролью "ais"

  Сценарий: Поиск идёт по наименованию
    Когда он запрашивает список с параметром "search" = "Кольца"
    Тогда "total" равно 2
    И "items" содержит записи "Кольца разные" и "Кольца обручальные"

  Сценарий: Тип изделия в поиске не участвует
    Когда он запрашивает список с параметром "search" = "Ювелирные"
    Тогда "items" пустой, "total" равно 0

  Сценарий: Ничего не найдено — пустой результат, а не ошибка
    Когда он запрашивает список с параметрами из файла "AR-PT-LIST-001.request.not-found.json"
    Тогда код ответа равен 200
    И тело ответа равно содержимому файла "AR-PT-LIST-001.response.200.empty.json"
```

## FR-PT-LIST-009. Фильтрация видов изделий {#fr-pt-list-009 .collapsed}

- **Использует**: [SF-PT-LIST][], [DR-PT-LIST-001][], [FR-G-FILTER-001][]
- **Используется в**: [AR-PT-LIST-001][], [FR-PT-LIST-006][]
- **Описание**: Система отбирает записи справочника по условиям фильтров по правилам [FR-G-FILTER-001][].
- **Условие**: Выполнено условие [FR-PT-LIST-001][]; передан хотя бы один параметр фильтра.
- **Результат**: Доступны фильтры из таблицы; условия объединяются по «и» с поиском и между собой, границы периодов
включаются ([FR-G-FILTER-001][]).

| Параметр | Вид условия | Допустимые значения |
| :--- | :--- | :--- |
| `name` | Вхождение | Строка до 150 символов |
| `product_group` | Выбор | `JEWELRY`, `WEIGHT_PRODUCTS`, `WATCH_CASES` ([DR-PT-001][]) |
| `default_streak_count`, `wholesale_gold_streak_count` | Число | Больше 0, не больше 999.99, до 2 знаков после точки |
| `stamp_impressions_count` | Целое | Больше 0 |
| `is_active` | Логическое | `true`, `false` |
| `created_at_from`, `created_at_to` | Период | Дата и время ISO 8601 в UTC |
| `updated_at_from`, `updated_at_to` | Период | Дата и время ISO 8601 в UTC |

- **Показатели (NFR)**: Время ответа с фильтрами — по показателю [FR-PT-LIST-001][].

### Эталоны {#fr-pt-list-009-examples .collapsed}

Сочетание фильтров по типу и периоду создания — запрос и ответ из [FR-PT-LIST-001][].

### Критерии приёмки (AC) {#fr-pt-list-009-ac .collapsed}

Общие правила (границы периода, одна граница, объединение с поиском, ошибки параметров) проверяются сценариями

## FR-PT-LIST-003. Сортировка списка видов изделий {#fr-pt-list-003 .collapsed}

- **Использует**: [SF-PT-LIST][], [DR-PT-LIST-001][], [FR-G-SORT-001][]
- **Используется в**: [AR-PT-LIST-001][], [FR-PT-LIST-007][]
- **Описание**: Система упорядочивает записи справочника по правилам сортировки [FR-G-SORT-001][] с порядком по
умолчанию и правилами сравнения справочника.
- **Условие**: Выполнено условие [FR-PT-LIST-001][].
- **Результат**:
    - **Порядок по умолчанию** (сортировка не выбрана): по `created_at`, затем по `pk`, по возрастанию.
    - **Сортируемые поля** (`sort_by`): `name_nominative`, `product_group`, `default_streak_count`,
      `wholesale_gold_streak_count`, `stamp_impressions_count`, `is_active`, `created_at`, `updated_at`.
    - **Тип изделия** (`product_group`) сравнивается по названию по правилам русского алфавита: по возрастанию
      «Весовые изделия», «Часовые корпуса», «Ювелирные изделия».
    - Остальные поля сравниваются по типу данных, направление и дополнительный порядок — по [FR-G-SORT-001][].
- **Показатели (NFR)**: Время ответа с сортировкой — по показателю [FR-PT-LIST-001][].

### Критерии приёмки (AC) {#fr-pt-list-003-ac .collapsed}

Направление по умолчанию, дополнительный порядок и ошибки параметров проверяются сценариями [FR-G-SORT-001][].

```gherkin
# language: ru
@FR-PT-LIST-003 @AR-PT-LIST-001
Функционал: Сортировка списка видов изделий

  Предыстория:
    Дано в справочнике записи из файла "PT.fixture.json"
    И аутентифицированный пользователь с ролью "ais"

  Сценарий: Порядок по умолчанию — по дате создания
    Когда он запрашивает список с параметром "page_size" = 25
    Тогда записи "items" упорядочены по "created_at" по возрастанию

  Структура сценария: Сортировка по полю справочника
    Когда он запрашивает список с параметрами "sort_by" = "<поле>", "sort_order" = "<направление>",
      "page_size" = 25
    Тогда первая запись "items" — "<первая>"
    И последняя запись "items" — "<последняя>"

    Примеры:
      | поле                        | направление | первая             | последняя          |
      | name_nominative             | asc         | Браслеты           | Часы               |
      | name_nominative             | desc        | Часы               | Браслеты           |
      | is_active                   | asc         | Брелоки            | Замки шпрингельные |
      | is_active                   | desc        | Кольца разные      | Брелоки            |
      | product_group               | asc         | Вилки              | Замки шпрингельные |
      | product_group               | desc        | Кольца разные      | Ножи               |
      | wholesale_gold_streak_count | desc        | Браслеты           | Замки шпрингельные |
      | created_at                  | desc        | Замки шпрингельные | Кольца разные      |
```

## FR-PT-LIST-004. Отказ в получении списка видов изделий {#fr-pt-list-004 .collapsed}

- **Использует**: [SF-PT-LIST][], [DR-PT-LIST-001][], [AR-001][]
- **Используется в**: [AR-PT-LIST-001][], [FR-PT-LIST-005][]
- **Описание**: Система отклоняет запрос списка по общим правилам [AR-001][], если пользователь не аутентифицирован,
не имеет ни одной роли справочника или параметры некорректны.
- **Порядок проверок**: аутентификация (`401`), право просмотра (`403`), параметры (`400`, все найденные ошибки в
порядке параметров [AR-PT-LIST-001][]) — по [AR-001][].
- **Показатели (NFR)**: Ответ с отказом возвращается не дольше показателя [FR-PT-LIST-001][].

### Проверки параметров {#fr-pt-list-004-checks .collapsed}

Проверки параметров пагинации, поиска и направления сортировки, а также пустые, повторные и лишние параметры — по
[FR-G-PAG-001][], [FR-G-SEARCH-001][], [FR-G-SORT-001][] и [AR-001][]. Проверки, которые задаёт справочник:

| Параметр | Проверка | Код ошибки в `details` |
| :--- | :--- | :--- |
| `sort_by` | Значение — поле из перечня [FR-PT-LIST-003][] | `INVALID_VALUE` |
| Параметры фильтров | Значение соответствует таблице [FR-PT-LIST-009][] | Коды [FR-G-FILTER-001][] |

### Коды ответов при отказе {#fr-pt-list-004-responses .collapsed}

| Код ответа | Код ошибки `code` | Когда |
| :--- | :--- | :--- |
| `400` | `VALIDATION_ERROR` | Одна или несколько проверок параметров не пройдены |
| `401` | `UNAUTHORIZED` | Пользователь не аутентифицирован |
| `403` | `FORBIDDEN` | У пользователя нет ни одной роли справочника |
| `500` | `INTERNAL_ERROR` | Внутренняя ошибка: список не возвращается |

### Эталоны отказов {#fr-pt-list-004-examples .collapsed}

#### 400. Ошибки в параметрах запроса {#fr-pt-list-004-examples-400 .collapsed}

Запрос нарушает сразу несколько проверок: номер страницы меньше 1, недопустимый размер страницы, неизвестное поле
и направление сортировки, недопустимый тип изделия, нечисловое количество, перевёрнутый период и лишний параметр.

Параметры запроса:

```json
--8<-- "requirements/features/dict-product-type/sf-list/api/AR-PT-LIST-001.request.invalid.json"
```

Ответ `400 Bad Request`:

```json
--8<-- "requirements/features/dict-product-type/sf-list/api/AR-PT-LIST-001.response.400.json"
```

#### 403. Нет права просмотра {#fr-pt-list-004-examples-403 .collapsed}

Корректный запрос отправлен пользователем, у которого нет ни одной роли справочника ([SF-PT-LIST][]).

Ответ `403 Forbidden`:

```json
--8<-- "requirements/global/api/error.403.json"
```

Ответы `401` и `500` — общие эталоны [AR-001][].

### Критерии приёмки (AC) {#fr-pt-list-004-ac .collapsed}

Отказы `401` и `500` проверяются общими сценариями [AR-001][], ошибки отдельных параметров пагинации, поиска,
сортировки и фильтров — сценариями глобальных функциональностей.

```gherkin
# language: ru
@FR-PT-LIST-004 @AR-PT-LIST-001
Функционал: Отказ в получении списка видов изделий

  Сценарий: Все ошибки параметров перечислены в одном ответе
    Дано аутентифицированный пользователь с ролью "ais"
    Когда он запрашивает список с параметрами из файла "AR-PT-LIST-001.request.invalid.json"
    Тогда код ответа равен 400
    И тело ответа равно содержимому файла "AR-PT-LIST-001.response.400.json"

  Структура сценария: Ошибка в параметре справочника
    Дано аутентифицированный пользователь с ролью "ais"
    Когда он отправляет запрос "GET /api/v1/product-types?<строка запроса>"
    Тогда код ответа равен 400
    И "details" содержит одну ошибку с полем "<поле>" и кодом "<код>"

    Примеры:
      | строка запроса             | поле                    | код           |
      | sort_by=color              | sort_by                 | INVALID_VALUE |
      | product_group=GOLD         | product_group           | INVALID_VALUE |
      | default_streak_count=0.555 | default_streak_count    | INVALID_SCALE |
      | stamp_impressions_count=0  | stamp_impressions_count | OUT_OF_RANGE  |

  Сценарий: Нет права просмотра
    Дано аутентифицированный пользователь без ролей справочника (например, пользователь другой подсистемы)
    Когда он запрашивает список без параметров
    Тогда код ответа равен 403
    И тело ответа равно содержимому файла "error.403.json"
```

## Экран списка: общие правила {#fr-pt-list-ui .collapsed}

Требования `FR-PT-LIST-005`–`008` описывают экран «Виды изделий». Экран построен по шаблону экрана справочника
[UI-G-DICT-001][] и описывает только значения справочника и отклонения от шаблона.

- **Адрес экрана**: `/dictionaries/product-types` (см. `UI-G-DICT-001.H01`).
- **Источник данных**: операция [AR-PT-LIST-001][]; экран не хранит записи между открытиями.

### Атрибуты `data-testid` {#fr-pt-list-ui-testid .collapsed}

## AR-PT-LIST-001. Получение списка видов изделий (API) {#ar-pt-list-001 .collapsed}

- **Использует**: [AR-PT-001][], [FR-PT-LIST-001][], [FR-PT-LIST-002][], [FR-PT-LIST-009][], [FR-PT-LIST-003][],
[FR-PT-LIST-004][], [DR-PT-LIST-001][], [FR-G-PAG-001][], [FR-G-SORT-001][], [FR-G-SEARCH-001][], [FR-G-FILTER-001][]
- **Метод и путь**: `GET /api/v1/product-types`
- **Права доступа**: роли из [SF-PT-LIST][]
- **Параметры**: только в строке запроса, тела у запроса нет. Все параметры необязательны.
- **Форматы**: Тело ответа — JSON в кодировке UTF-8. Количества — JSON-числа, в строке запроса — с точкой (`0.5`).
Идентификатор `pk` — UUID. Дата и время — ISO 8601 в UTC, например `2026-11-20T09:30:15Z`; в строке запроса
кодируются по правилам URL. Логические значения — `true` и `false`.

### Параметры запроса {#ar-pt-list-001-params .collapsed}

| Параметр | Тип | По умолчанию | Назначение |
| :--- | :--- | :--- | :--- |
| `page`, `page_size` | По [FR-G-PAG-001][] | 1, 10 | Номер и размер страницы |
| `search` | Строка до 150 символов | — | Поиск по вхождению в `name_nominative` ([FR-G-SEARCH-001][]) |
| `sort_by` | Поле из [FR-PT-LIST-003][] | — | Поле сортировки; без него — порядок по умолчанию |
| `sort_order` | `asc`, `desc` | `asc` | Направление сортировки по [FR-G-SORT-001][] |
| `name` | Строка до 150 символов | — | Фильтр: наименование содержит подстроку |
| `product_group` | `JEWELRY`, `WEIGHT_PRODUCTS`, `WATCH_CASES` | — | Фильтр: тип изделия |
| `default_streak_count` | Число | — | Фильтр: базовое количество натиров |
| `wholesale_gold_streak_count` | Число | — | Фильтр: натиры для золотых изделий оптовой торговли |
| `stamp_impressions_count` | Целое число | — | Фильтр: количество наложенных оттисков |
| `is_active` | `true`, `false` | — | Фильтр: статус |
| `created_at_from`, `created_at_to` | Дата и время | — | Фильтр: период создания, границы включаются |
| `updated_at_from`, `updated_at_to` | Дата и время | — | Фильтр: период изменения, границы включаются |

Фильтры следуют соглашениям [FR-G-FILTER-001][]. Схемы параметров и ответа ссылаются на общие определения
`global/api/list.schema.json` (`page`, `page_size`, `search`, `sort_order`, конверт `page_envelope`).

Пример строки запроса для эталона `AR-PT-LIST-001.request.json`:

```text
GET /api/v1/product-types?page=1&page_size=10&product_group=JEWELRY
    &created_at_from=2026-11-17T21%3A00%3A00Z&created_at_to=2026-11-19T20%3A59%3A00Z
    &sort_by=created_at&sort_order=asc
```

### Ответы {#ar-pt-list-001-responses .collapsed}

| Код ответа | Когда | Тело | Эталон |
| :--- | :--- | :--- | :--- |
| `200` | Страница получена | Записи, номер и размер страницы, `total` | [файл](api/AR-PT-LIST-001.response.200.json) |
| `400` | Ошибки в параметрах | Ошибка с перечнем по параметрам | [файл](api/AR-PT-LIST-001.response.400.json) |
| `401` | Пользователь не аутентифицирован | Ошибка | [error.401.json](../../../global/api/error.401.json) |
| `403` | Нет права просмотра | Ошибка | [error.403.json](../../../global/api/error.403.json) |
| `500` | Внутренняя ошибка | Ошибка | [error.500.json](../../../global/api/error.500.json) |

Тела ответов с ошибками (`400`–`500`) соответствуют общей схеме
[error.response.schema.json](../../../global/api/error.response.schema.json); в `details[].field` указывается имя
параметра.

### Файлы эталонов и схем {#ar-pt-list-001-files .collapsed}

Файлы лежат в каталоге [api/](api/) рядом со страницей. Автотесты берут параметры, ответы и схемы из
этих же файлов, поэтому страница и тесты не расходятся.

| Файл | Назначение |
| :--- | :--- |
| `AR-PT-LIST-001.request.schema.json` | Схема параметров запроса после разбора строки запроса |
| `AR-PT-LIST-001.request.json` | Корректные параметры: фильтры по типу и периоду, сортировка |
| `AR-PT-LIST-001.request.not-found.json` | Параметры, по которым ничего не найдено |
| `AR-PT-LIST-001.request.invalid.json` | Параметры с ошибками (ответ `400`) |
| `AR-PT-LIST-001.response.200.schema.json` | Схема тела ответа `200` |
| `AR-PT-LIST-001.response.200.json` | Эталон ответа `200` на `request.json` |
| `AR-PT-LIST-001.response.200.empty.json` | Эталон ответа `200` без записей |
| `AR-PT-LIST-001.response.400.json` | Эталон ответа `400` на `request.invalid.json` |

Эталоны ответов `401`, `403` и `500` общие для всех операций и лежат в глобальном каталоге:
[error.401.json](../../../global/api/error.401.json), [error.403.json](../../../global/api/error.403.json),
[error.500.json](../../../global/api/error.500.json) ([AR-001][]).
