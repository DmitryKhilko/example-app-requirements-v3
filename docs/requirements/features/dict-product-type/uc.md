# СЦЕНАРИИ ИСПОЛЬЗОВАНИЯ {#uc}

Сценарии описывают цели пользователя при работе со справочником видов изделий ([F-PT][]) и диалог «Намерение —
Реакция». Состав полей, ограничения, размеры страниц, тексты сообщений и права доступа задаются в спецификациях
детальной функциональности ([SF-PT-LIST][], [SF-PT-READ][], [SF-PT-CREATE][], [SF-PT-UPDATE][], [SF-PT-ACTIVATION][],
[SF-PT-DELETE][]) и требованиях к данным ([DR-PT-CREATE-001][]).

Во всех сценариях **актор** — пользователь, которому предоставлено право ведения справочника видов изделий (состав ролей
определяется в спецификациях детальной функциональности).

## UC-PT-001. Просмотреть список видов изделий {#uc-pt-001 .collapsed}

- **Описание**: Пользователь получает перечень видов изделий с их параметрами (тип изделия, количество натиров,
  количество наложенных оттисков, статус, даты создания и изменения), чтобы оценить актуальность справочника и выбрать
  запись для дальнейшей работы.
- **Актор**: Пользователь с правом ведения справочника.
- **Использует**: [F-PT][], [SF-PT-LIST][]
- **Предусловие**: Пользователь аутентифицирован и имеет право просмотра справочника.

**Основной поток:**

1. Актор запрашивает переход к справочнику видов изделий из перечня справочников.
2. Система предоставляет первую страницу списка видов изделий с постраничной навигацией и сообщает общее количество
   записей и диапазон показанных записей. Порядок записей по умолчанию не задан пользователем.
3. Актор просматривает список.

**Альтернативные потоки:**

- **А1. Справочник пуст (на шаге 2):**
    1. В справочнике нет ни одной записи.
    2. Система сообщает, что записей пока нет и что новые записи появятся в списке после добавления.
    3. Сценарий завершается; актор может перейти к созданию записи ([UC-PT-006][]).
- **А2. Переход на другую страницу (на шаге 3):**
    1. Актор запрашивает следующую, предыдущую или конкретную страницу списка.
    2. Система предоставляет записи запрошенной страницы и обновляет сведения о диапазоне показанных записей.
    3. Сценарий возвращается к шагу 3.
- **А3. Изменение количества записей на странице (на шаге 3):**
    1. Актор указывает количество записей на странице из доступного перечня.
    2. Система предоставляет первую страницу списка с указанным количеством записей и пересчитывает количество страниц.
    3. Сценарий возвращается к шагу 3.
- **А4. Возврат к перечню справочников (на любом шаге):**
    1. Актор запрашивает возврат к перечню справочников.
    2. Система предоставляет перечень справочников. Сценарий завершается.

**Постусловие:** Актор видит актуальный список видов изделий; данные справочника не изменились.

## UC-PT-002. Найти вид изделий по наименованию {#uc-pt-002 .collapsed}

- **Описание**: Пользователь быстро находит нужный вид изделий, указав часть его наименования, чтобы не просматривать
  весь список.
- **Актор**: Пользователь с правом ведения справочника.
- **Использует**: [SF-PT-LIST][]
- **Предусловие**: Актор просматривает список видов изделий ([UC-PT-001][]).

**Основной поток:**

1. Актор задаёт строку поиска (часть наименования).
2. Система отбирает записи, наименование которых содержит заданную строку, и предоставляет первую страницу результата
   с общим количеством найденных записей. Ранее применённые фильтры и порядок сортировки сохраняются.
3. Актор просматривает результат поиска.

**Альтернативные потоки:**

- **А1. Ничего не найдено (на шаге 2):**
    1. Ни одна запись не соответствует строке поиска.
    2. Система сообщает, что записи не найдены.
    3. Сценарий возвращается к шагу 1.
- **А2. Сброс поиска (на шаге 3):**
    1. Актор запрашивает очистку строки поиска.
    2. Система предоставляет список без ограничения по наименованию с учётом остальных применённых условий.
    3. Сценарий завершается.

**Постусловие:** Список ограничен записями, наименование которых содержит строку поиска.

## UC-PT-003. Отфильтровать список видов изделий {#uc-pt-003 .collapsed}

- **Описание**: Пользователь отбирает записи по одному или нескольким условиям (наименование, тип изделия, базовое
  количество натиров, количество натиров для золотых изделий оптовой торговли, количество наложенных оттисков, статус,
  период создания, период изменения), чтобы работать только с нужной частью справочника.
- **Актор**: Пользователь с правом ведения справочника.
- **Использует**: [SF-PT-LIST][], [DR-PT-CREATE-001][]
- **Предусловие**: Актор просматривает список видов изделий ([UC-PT-001][]).

**Основной поток:**

1. Актор запрашивает задание условий отбора.
2. Система предоставляет перечень доступных условий отбора с текущими значениями (по умолчанию условия не заданы).
3. Актор указывает значения одного или нескольких условий: тип изделия и статус — из доступного перечня, периоды
   создания и изменения — как диапазон даты и времени, остальные — как значения — и подтверждает применение.
4. Система отбирает записи, удовлетворяющие всем заданным условиям одновременно, предоставляет первую страницу
   результата с общим количеством записей, показывает перечень применённых условий и их количество.
5. Актор просматривает отфильтрованный список.

**Альтернативные потоки:**

- **А1. Ничего не найдено (на шаге 4):**
    1. Ни одна запись не удовлетворяет заданным условиям.
    2. Система сообщает, что записи не найдены, и сохраняет перечень применённых условий.
    3. Сценарий возвращается к шагу 1.
- **А2. Отмена одного условия (на шаге 5):**
    1. Актор запрашивает отмену одного из применённых условий.
    2. Система исключает это условие, повторно отбирает записи по оставшимся условиям и обновляет перечень применённых
       условий и их количество.
    3. Сценарий возвращается к шагу 5.
- **А3. Сброс всех условий (на шаге 3 или 5):**
    1. Актор запрашивает сброс всех условий отбора.
    2. Система очищает все условия и предоставляет список без ограничений по условиям отбора.
    3. Сценарий завершается.
- **А4. Отказ от задания условий (на шаге 3):**
    1. Актор отказывается от задания условий без их применения.
    2. Система сохраняет ранее применённые условия без изменений.
    3. Сценарий завершается.

**Постусловие:** Список содержит только записи, удовлетворяющие всем применённым условиям; актор видит перечень
применённых условий.

## UC-PT-004. Упорядочить список видов изделий {#uc-pt-004 .collapsed}

- **Описание**: Пользователь упорядочивает список по одному из атрибутов (наименование, тип изделия, количество натиров,
  количество наложенных оттисков, статус, дата создания, дата изменения), чтобы быстрее найти нужные записи или
  сравнить их.
- **Актор**: Пользователь с правом ведения справочника.
- **Использует**: [SF-PT-LIST][]
- **Предусловие**: Актор просматривает список видов изделий ([UC-PT-001][]).

**Основной поток:**

1. Актор запрашивает упорядочивание списка по выбранному атрибуту.
2. Система упорядочивает записи по выбранному атрибуту по возрастанию, обозначает атрибут и направление сортировки и
   предоставляет первую страницу результата. Применённые поиск и фильтры сохраняются.
3. Актор просматривает упорядоченный список.

**Альтернативные потоки:**

- **А1. Смена направления (на шаге 3):**
    1. Актор повторно запрашивает упорядочивание по тому же атрибуту.
    2. Система меняет направление сортировки на противоположное и обновляет список.
    3. Сценарий возвращается к шагу 3.
- **А2. Упорядочивание по другому атрибуту (на шаге 3):**
    1. Актор запрашивает упорядочивание по другому атрибуту.
    2. Система отменяет сортировку по прежнему атрибуту и упорядочивает записи по новому атрибуту по возрастанию.
    3. Сценарий возвращается к шагу 3.
- **А3. Возврат к порядку по умолчанию (на шаге 3, после А1):**
    1. Актор ещё раз запрашивает упорядочивание по тому же атрибуту.
    2. Система отменяет сортировку и предоставляет список в порядке по умолчанию.
    3. Сценарий завершается.

**Постусловие:** Список упорядочен по одному выбранному атрибуту в выбранном направлении либо находится в порядке по
умолчанию.

## UC-PT-005. Настроить состав отображаемых атрибутов списка {#uc-pt-005 .collapsed}

- **Описание**: Пользователь оставляет в списке только нужные для работы атрибуты, чтобы список был компактнее.
- **Актор**: Пользователь с правом ведения справочника.
- **Использует**: [SF-PT-LIST][]
- **Предусловие**: Актор просматривает список видов изделий ([UC-PT-001][]).

**Основной поток:**

1. Актор запрашивает настройку состава отображаемых атрибутов.
2. Система предоставляет перечень атрибутов списка с отметкой отображаемых (по умолчанию отображаются все).
3. Актор указывает атрибуты, которые нужно отображать, и подтверждает применение.
4. Система отображает список только с указанными атрибутами и обозначает, что состав атрибутов изменён.

**Альтернативные потоки:**

- **А1. Отображение всех атрибутов (на шаге 3):**
    1. Актор запрашивает отметку всех атрибутов.
    2. Система отмечает все атрибуты перечня.
    3. Сценарий возвращается к шагу 3.
- **А2. Отказ от настройки (на шаге 3):**
    1. Актор отказывается от настройки без применения.
    2. Система сохраняет прежний состав отображаемых атрибутов.
    3. Сценарий завершается.

**Постусловие:** Список отображается с выбранным составом атрибутов; данные справочника не изменились.

## UC-PT-006. Создать вид изделий {#uc-pt-006 .collapsed}

- **Описание**: Пользователь добавляет в справочник новый вид изделий, чтобы он стал доступен для выбора в заявлениях
  на проведение пробирных работ и отображался в иных документах.
- **Актор**: Пользователь с правом создания записей справочника.
- **Использует**: [SF-PT-CREATE][], [DR-PT-CREATE-001][], [FR-PT-CREATE-001][], [FR-PT-CREATE-002][]
- **Предусловие**: Актор просматривает список видов изделий ([UC-PT-001][]) и имеет право создания записей.

**Основной поток:**

1. Актор запрашивает создание нового вида изделий.
2. Система предоставляет форму для ввода данных: наименование и тип изделия не заполнены, количество натиров (базовое
   и для золотых изделий оптовой торговли) и количество наложенных оттисков содержат значения по умолчанию, статус
   «Действует».
3. Актор указывает наименование, тип изделия из доступного перечня, при необходимости корректирует количественные
   параметры и статус и подтверждает сохранение.
4. Система проверяет корректность и уникальность данных, сохраняет запись, фиксирует дату и время создания и
   изменения, информирует актора об успешном добавлении и предоставляет обновлённый список, в котором есть новая запись.

**Альтернативные потоки:**

- **А1. Данные не прошли проверку (на шаге 4):**
    1. Не указаны обязательные данные или значения не соответствуют ограничениям.
    2. Система отклоняет сохранение, указывает каждое некорректное значение и причину, сохраняя введённые данные.
    3. Сценарий возвращается к шагу 3.
- **А2. Вид изделий уже существует (на шаге 4):**
    1. В справочнике уже есть запись с таким же наименованием и типом изделия.
    2. Система отклоняет сохранение и сообщает, что такая запись уже существует, сохраняя введённые данные.
    3. Сценарий возвращается к шагу 3.
- **А3. Отказ от создания (на шаге 3):**
    1. Актор отказывается от создания записи.
    2. Система не сохраняет данные и предоставляет список без изменений.
    3. Сценарий завершается.
- **А4. Нет права или ошибка системы (на шаге 4):**
    1. У актора нет права создания записей, сеанс завершён или при сохранении произошла внутренняя ошибка.
    2. Система отклоняет операцию и информирует актора о причине.
    3. Сценарий завершается.

**Постусловие:** В справочнике создана новая запись вида изделий с указанными данными и статусом; дата создания и
дата изменения совпадают.

## UC-PT-007. Изменить вид изделий {#uc-pt-007 .collapsed}

- **Описание**: Пользователь исправляет данные существующего вида изделий (наименование, тип изделия, количество
  натиров, количество наложенных оттисков), чтобы справочник оставался достоверным.
- **Актор**: Пользователь с правом изменения записей справочника.
- **Использует**: [SF-PT-READ][], [SF-PT-UPDATE][]
- **Предусловие**: Актор просматривает список видов изделий ([UC-PT-001][]), запись существует, актор имеет право
  изменения записей.

**Основной поток:**

1. Актор выбирает вид изделий для изменения.
2. Система предоставляет форму с текущими данными выбранной записи.
3. Актор изменяет необходимые данные и подтверждает сохранение.
4. Система проверяет корректность и уникальность данных, сохраняет изменения, фиксирует дату и время изменения,
   информирует актора об успешном сохранении и предоставляет обновлённый список.

**Альтернативные потоки:**

- **А1. Данные не прошли проверку (на шаге 4):**
    1. Не указаны обязательные данные или значения не соответствуют ограничениям.
    2. Система отклоняет сохранение, указывает каждое некорректное значение и причину, сохраняя введённые данные.
    3. Сценарий возвращается к шагу 3.
- **А2. Вид изделий уже существует (на шаге 4):**
    1. В справочнике есть другая запись с таким же наименованием и типом изделия.
    2. Система отклоняет сохранение и сообщает, что такая запись уже существует.
    3. Сценарий возвращается к шагу 3.
- **А3. Отказ от изменения (на шаге 3):**
    1. Актор отказывается от изменения.
    2. Система не сохраняет изменения и предоставляет список без изменений.
    3. Сценарий завершается.
- **А4. Запись больше не существует (на шаге 2 или 4):**
    1. Запись удалена другим пользователем.
    2. Система сообщает, что запись не найдена, и предоставляет обновлённый список.
    3. Сценарий завершается.
- **А5. Нет права или ошибка системы (на шаге 4):**
    1. У актора нет права изменения записей, сеанс завершён или при сохранении произошла внутренняя ошибка.
    2. Система отклоняет операцию и информирует актора о причине.
    3. Сценарий завершается.

**Постусловие:** Данные записи изменены, дата изменения обновлена, дата создания не изменилась.

## UC-PT-008. Изменить статус вида изделий {#uc-pt-008 .collapsed}

- **Описание**: Пользователь деактивирует вид изделий, чтобы скрыть его от выбора в документах, не удаляя запись, или
  снова активирует ранее деактивированную запись.
- **Актор**: Пользователь с правом изменения записей справочника.
- **Использует**: [SF-PT-ACTIVATION][]
- **Предусловие**: Актор просматривает список видов изделий ([UC-PT-001][]), запись существует, актор имеет право
  изменения записей.

**Основной поток:**

1. Актор выбирает вид изделий для изменения.
2. Система предоставляет текущие данные записи, включая статус.
3. Актор указывает новый статус («Действует» или «Не действует») и подтверждает сохранение.
4. Система сохраняет новый статус, фиксирует дату и время изменения, информирует актора об успешном сохранении и
   предоставляет обновлённый список, в котором у записи отображается новый статус.

**Альтернативные потоки:**

- **А1. Отказ от изменения статуса (на шаге 3):**
    1. Актор отказывается от изменения.
    2. Система сохраняет прежний статус записи.
    3. Сценарий завершается.
- **А2. Запись больше не существует, нет права или ошибка системы (на шаге 4):**
    1. Запись удалена другим пользователем, у актора нет права изменения или произошла внутренняя ошибка.
    2. Система отклоняет операцию и информирует актора о причине.
    3. Сценарий завершается.

**Постусловие:** Запись имеет новый статус. Запись со статусом «Не действует» недоступна для выбора в новых документах
и остаётся в справочнике.

## UC-PT-009. Удалить виды изделий {#uc-pt-009 .collapsed}

- **Описание**: Пользователь удаляет из справочника одну или несколько записей, внесённых ошибочно и нигде не
  используемых, чтобы в справочнике не оставалось лишних видов изделий.
- **Актор**: Пользователь с правом удаления записей справочника.
- **Использует**: [SF-PT-DELETE][]
- **Предусловие**: Актор просматривает список видов изделий ([UC-PT-001][]), в списке есть хотя бы одна запись, актор
  имеет право удаления записей.

**Основной поток:**

1. Актор отмечает одну или несколько записей для удаления.
2. Система обозначает отмеченные записи, сообщает количество отмеченных записей и общее количество записей и
   предоставляет возможность удалить отмеченные записи или снять отметку.
3. Актор запрашивает удаление отмеченных записей.
4. Система запрашивает подтверждение удаления и сообщает количество записей к удалению.
5. Актор подтверждает удаление.
6. Система проверяет, что ни одна из отмеченных записей не используется в других сущностях системы, полностью удаляет
   записи из базы данных, информирует актора о количестве удалённых записей и предоставляет обновлённый список.

**Альтернативные потоки:**

- **А1. Отметка всех записей страницы (на шаге 1):**
    1. Актор запрашивает отметку всех записей текущей страницы.
    2. Система отмечает все записи текущей страницы.
    3. Сценарий продолжается с шага 2.
- **А2. Снятие отметки (на шаге 2):**
    1. Актор снимает отметку с одной записи или запрашивает снятие отметки со всех записей.
    2. Система снимает отметку; если отмеченных записей не осталось, возможность удаления становится недоступной.
    3. Сценарий возвращается к шагу 1 или завершается.
- **А3. Отказ от удаления (на шаге 5):**
    1. Актор отказывается от удаления.
    2. Система не удаляет записи и сохраняет отметку записей.
    3. Сценарий возвращается к шагу 2.
- **А4. Запись используется в других сущностях (на шаге 6):**
    1. Хотя бы одна отмеченная запись используется в других сущностях системы (например, в заявлениях).
    2. Система отклоняет удаление целиком, сообщает, какие записи используются, и не удаляет ни одну из отмеченных
       записей (правило неделимого удаления задано в [SF-PT-DELETE][] и ждёт подтверждения).
    3. Сценарий завершается.
- **А5. Нет права или ошибка системы (на шаге 6):**
    1. У актора нет права удаления, запись уже удалена другим пользователем или произошла внутренняя ошибка.
    2. Система отклоняет операцию, информирует актора о причине и предоставляет обновлённый список.
    3. Сценарий завершается.

**Постусловие:** Удалённые записи физически отсутствуют в базе данных и не могут быть восстановлены; если хотя бы одна
отмеченная запись используется, ни одна запись не удаляется.

**Допущения:**

- **UC-PT-009.H01**
    - **Статус**: принято
    - **Подтверждает**: владелец справочника
    - **Допущение**: Удаление полное (физическое): запись, которая не используется в других сущностях, удаляется из
      базы данных; мягкое удаление (статус «Удалена») не применяется. Скрыть запись от выбора без удаления можно
      деактивацией ([UC-PT-008][]).
