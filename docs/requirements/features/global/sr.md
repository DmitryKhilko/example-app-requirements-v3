# СИСТЕМНЫЕ ТРЕБОВАНИЯ {#sr}

## SR-001. Рабочее место пользователя {#sr-001 .collapsed}

- **Используется в**: [NFR-001][], [NFR-002][], все экраны продукта
- **Описание**: Среда, в которой интерфейс продукта работает полностью и проверяется автотестами.
- **Браузеры**: две последние стабильные версии Google Chrome, Microsoft Edge и Mozilla Firefox на дату выпуска версии
продукта (см. `H01`).
- **Экран**: ширина окна браузера не меньше 1280px; масштаб 100–200 %. Мобильные устройства и планшеты не
поддерживаются ([дизайн-система][design-system]).
- **Проверка**: автотесты интерфейса выполняются в Chrome; ручная проверка перед сдачей — в Edge и Firefox.

### Допущения {#sr-001-assumptions .collapsed}

- **SR-001.H01**
    - **Статус**: требует подтверждения
    - **Подтверждает**: заказчик
    - **Допущение**: Перечень браузеров принят по распространённым браузерам рабочих мест; если в ведомстве
      используются другие браузеры (например, отечественные сборки Chromium), их нужно добавить в перечень.

## SR-002. Технический стандарт {#sr-002 .collapsed}

- **Используется в**: [AR-001][], [NFR-003][], [NFR-004][], код и автотесты продукта
- **Описание**: Технические решения, которые код продукта и автотесты принимают как заданные: стек, структура
репозитория кода, слои и правила вызовов, обработка ошибок, база данных, временная аутентификация. ИИ-агент и
разработчик не меняют эти решения сами: изменение — через правку этого требования.

### Стек {#sr-002-stack .collapsed}

| Слой | Технология |
| :--- | :--- |
| Бэкенд | Python, FastAPI, Pydantic |
| Доступ к данным и миграции | SQLAlchemy 2, Alembic (см. `H01`) |
| База данных | PostgreSQL с расширением `pg_trgm` |
| Фронтенд | React, TypeScript, сборка Vite (см. `H02`) |
| Тип и клиент API на фронтенде | openapi-typescript по эталонному OpenAPI требований |
| Автотесты API | pytest, pytest-bdd, httpx, jsonschema |
| Автотесты интерфейса | Playwright (TypeScript), axe-core |
| Нагрузочные замеры | k6 ([NFR-001][]) |

Версии фиксируются в файлах зависимостей репозитория кода (`pyproject.toml`, `package-lock.json`). Библиотека вне
таблицы подключается только после правки этого требования.

### Репозиторий кода {#sr-002-repository .collapsed}

| Каталог | Содержимое |
| :--- | :--- |
| `backend/` | Приложение FastAPI и миграции Alembic |
| `frontend/` | Приложение React |
| `tests/api/` | Функции шагов и настройки pytest-bdd для сценариев `@api` |
| `tests/ui/` | Функции шагов и настройки Playwright для сценариев `@ui` и `@e2e` |
| `requirements/` | Репозиторий требований по тегу версии: только для чтения, в коммиты не попадает |

### Слои и правила вызовов {#sr-002-layers .collapsed}

- **Фронтенд** обращается к бэкенду только через `/api/v1` ([AR-001][]).
- **Бэкенд** разделён на слои; каждый слой вызывает только следующий:
    1. Маршруты (`api/`): разбор запроса, проверка прав, формирование ответа.
    2. Сервисы (`services/`): правила предметной области, транзакция, запись в журнал аудита ([NFR-003][]).
    3. Репозитории (`repositories/`): запросы к базе данных.
- Маршруты не обращаются к базе данных, репозитории не содержат правил предметной области.
- Проверка прав выполняется до проверки данных, в порядке [AR-001][].

### Ошибки {#sr-002-errors .collapsed}

- Все ответы с ошибкой — в формате [AR-001][] по схеме `error.response.schema.json`.
- Ошибки проверки данных FastAPI и Pydantic приводятся к ответу `400` с кодом `VALIDATION_ERROR` и элементами
  `details` с кодами из [AR-001][]. Ответ `422`, который FastAPI возвращает по умолчанию, не используется.
- Необработанное исключение даёт ответ `500` по эталону `error.500.json`; текст исключения в ответ не попадает.

### База данных {#sr-002-database .collapsed}

- Схема базы данных меняется только миграциями; одна миграция — одно изменение требований к данным (DR).
- Таблицы, поля, ограничения и индексы соответствуют DR функциональности.
- Дата и время хранятся в UTC с точностью до секунды ([NFR-004][]).
- Роль базы данных, под которой работает приложение, не имеет прав на изменение и удаление записей журнала аудита
  ([NFR-003][]).

### Временная аутентификация {#sr-002-auth .collapsed}

До решения о способе аутентификации (см. `Q01`) пользователь и его роли передаются тестовыми заголовками.

- **Заголовки**: `X-Test-User` — идентификатор пользователя, `X-Test-Roles` — коды ролей через запятую из
  [перечня ролей][roles]. Нет заголовка `X-Test-User` — пользователь не аутентифицирован (`401`).
- **Включение**: заголовки принимаются, только если приложение запущено с переменной окружения
  `RMS_TEST_AUTH=1`. Без неё любой запрос получает `401`. В продуктивной среде переменная не задаётся.
- **Реализация**: пользователя и роли определяет одна зависимость FastAPI (`get_current_user`); остальной код
  получает их только через неё. Настоящая аутентификация заменит эту зависимость, не меняя остальной код.
- **Автотесты**: шаги аутентификации каталога шагов передают заголовки. Сценарии истечения сессии
  ([SF-G-SESSION][session]) помечаются `@pending` и не выполняются, пока нет настоящей аутентификации.
