# ИНТЕРФЕЙСНЫЕ ТРЕБОВАНИЯ {#ui}

Критерии приёмки проверяются на каждом экране продукта. Эталонная реализация — экран «Виды изделий» и форма
изменения вида изделий. Скриншотов истёкшей сессии нет.

## UI-G-SESSION-001. Переход на вход и возврат на экран {#ui-g-session-001 .collapsed}

- **Использует**: [SF-G-SESSION][], [AR-001][]
- **Используется в**: [FR-PT-LIST-005][], [UI-G-FORM-001][], [UI-G-CONFIRM-001][]
- **Описание**: На ответ `401` любого запроса экран переводит пользователя на вход, а после входа возвращает его на
тот же адрес.
- **Условие**: Запрос экрана к API получил ответ `401` ([AR-001][]).
- **Результат**: Пользователь входит заново и продолжает работу на том же экране с теми же поиском, фильтрами,
сортировкой и страницей.
- **Показатели (NFR)**: Переход на вход начинается не позже 100 мс после ответа `401`; при нескольких одновременных
ответах `401` переход выполняется один раз.

### Поведение (UX) {#ui-g-session-001-ux .collapsed}

1. Ответ `401` не показывается уведомлением: экран сразу переходит на вход и передаёт текущий адрес экрана как
   адрес возврата.
2. Экран входа показывает сообщение «Сеанс завершён. Войдите снова.» (см. `H01`).
3. После успешного входа пользователь возвращается по адресу возврата; условия списка восстанавливаются из адреса
   ([UI-G-PAG-001][]).
4. Адрес возврата принимается только внутри продукта; внешний адрес заменяется главной страницей.
5. Несохранённые данные открытой формы не сохраняются (см. `H02`); открытые окна при возврате закрыты.
6. Если после входа у пользователя нет прав на экран, он видит состояние «Нет доступа» ([UI-G-TABLE-002][]).

### Критерии приёмки (AC) {#ui-g-session-001-ac .collapsed}

```gherkin
# language: ru
@UI-G-SESSION-001 @SF-G-SESSION @ui
Функционал: Переход на вход и возврат на экран

  Предыстория:
    Дано в справочнике видов изделий записи из файла "PT.fixture.json"
    И пользователь с ролью "ais" открыл экран "Виды изделий" на странице 2 с поиском "коль"

  Сценарий: Сессия истекла при работе со списком
    Дано сессия пользователя истекла
    Когда пользователь нажимает "pt-list-sort" с data-field "name_nominative"
    Тогда открыт экран входа с сообщением "Сеанс завершён. Войдите снова."
    И нет "toast"
    Когда пользователь входит с ролью "ais"
    Тогда открыт экран "Виды изделий"
    И "pt-list-search" содержит "коль"

  Сценарий: Сессия истекла при сохранении формы
    Дано открыта форма изменения записи "Брелоки"
    И сессия пользователя истекла
    Когда пользователь нажимает "pt-form-submit"
    Тогда открыт экран входа
    И запись "Брелоки" не изменилась

  Сценарий: Несколько ответов 401 — один переход
    Дано сессия пользователя истекла
    Когда экран одновременно получает два ответа 401
    Тогда переход на экран входа выполнен один раз

  Сценарий: Внешний адрес возврата не принимается
    Когда пользователь открывает экран входа с адресом возврата "https://example.com"
    И входит с ролью "ais"
    Тогда открыта главная страница продукта
```

### Допущения {#ui-g-session-001-assumptions .collapsed}

- **UI-G-SESSION-001.H01**
    - **Статус**: требует подтверждения
    - **Подтверждает**: владелец продукта
    - **Допущение**: Текст сообщения на экране входа — «Сеанс завершён. Войдите снова.»; экран входа не описан.
- **UI-G-SESSION-001.H02**
    - **Статус**: требует подтверждения
    - **Подтверждает**: владелец продукта
    - **Допущение**: Несохранённые данные открытой формы при истечении сессии теряются; сохранение черновика не
      требуется.
- **UI-G-SESSION-001.H03**
    - **Статус**: требует подтверждения
    - **Подтверждает**: архитектор
    - **Допущение**: Вход выполняется на отдельном экране продукта, а не во всплывающем окне поверх текущего экрана;
      способ задаёт технический стандарт.
