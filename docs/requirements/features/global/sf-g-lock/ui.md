# ИНТЕРФЕЙСНЫЕ ТРЕБОВАНИЯ {#ui}

Критерии приёмки проверяются на каждой операции изменения, которая подключает функциональность. Эталонная
реализация — изменение вида изделий (`PUT /api/v1/product-types/{pk}`, форма с приставкой `data-testid` `pt`) с
[тестовым набором][fixture]. Скриншотов одновременного изменения нет: экран описан по общим правилам формы и
уведомлений.

## UI-G-LOCK-001. Форма при одновременном изменении {#ui-g-lock-001 .collapsed}

- **Использует**: [SF-G-LOCK][], [FR-G-LOCK-001][], [UI-G-FORM-001][], [UI-G-TOAST-001][]
- **Используется в**: [FR-PT-UPDATE-003][]
- **Описание**: Форма изменения хранит версию прочитанной записи и при отказе `RECORD_MODIFIED` сообщает о нём, не
теряя введённых значений.
- **Условие**: Открыта форма изменения записи ([UI-G-FORM-001][]) для операции, которая подключает [SF-G-LOCK][].
- **Результат**: Пользователь узнаёт, что запись изменил другой пользователь, и может открыть её заново; чужие
изменения не перезаписываются.
- **Показатели (NFR)**: Уведомление появляется не позже 100 мс после ответа API.

### Поведение (UX) {#ui-g-lock-001-ux .collapsed}

1. При открытии форма заново читает запись операцией чтения (а не берёт данные из строки списка) и хранит
   `updated_at` из ответа (см. `H01`).
2. «Сохранить» отправляет сохранённое значение `updated_at` вместе с полями формы.
3. Ответ `409 RECORD_MODIFIED`: уведомление «Ошибка» с текстом «Запись изменил другой пользователь. Закройте окно и
   откройте запись снова.» ([UI-G-TOAST-001][]); окно остаётся открытым, введённые значения сохраняются, форма не
   перечитывает запись сама (см. `H02`).
4. После закрытия окна список перезагружается, чтобы показать текущие данные записи.

### Критерии приёмки (AC) {#ui-g-lock-001-ac .collapsed}

```gherkin
# language: ru
@UI-G-LOCK-001 @SF-G-LOCK @ui
Функционал: Форма при одновременном изменении

  Предыстория:
    Дано в справочнике видов изделий записи из файла "PT.fixture.json"
    И пользователь с ролью "ais" открыл экран "Виды изделий"

  Сценарий: Форма читает запись при открытии
    Когда пользователь нажимает строку "Зажимы для галстуков"
    Тогда отправлен запрос "GET /api/v1/product-types/00000000-0000-4000-8000-000000000007"
    И "pt-form-modal" показывает данные из ответа

  Сценарий: Запись изменил другой пользователь
    Дано открыта форма изменения записи "Зажимы для галстуков"
    И другой пользователь изменил эту запись
    Когда пользователь вводит "Зажимы галстучные" в "pt-form-name" и нажимает "pt-form-submit"
    Тогда виден "toast" с заголовком "Ошибка" и текстом
      "Запись изменил другой пользователь. Закройте окно и откройте запись снова."
    И "pt-form-modal" открыт, "pt-form-name" содержит "Зажимы галстучные"
    Когда пользователь закрывает окно и снова открывает запись
    Тогда форма показывает данные, сохранённые другим пользователем
```

### Допущения {#ui-g-lock-001-assumptions .collapsed}

- **UI-G-LOCK-001.H01**
    - **Статус**: требует подтверждения
    - **Подтверждает**: владелец продукта
    - **Допущение**: Форма изменения перед показом заново читает запись, а не берёт данные из строки списка: так в
      форме актуальные данные и `updated_at` для проверки одновременного изменения.
- **UI-G-LOCK-001.H02**
    - **Статус**: требует подтверждения
    - **Подтверждает**: владелец продукта
    - **Допущение**: При ответе `RECORD_MODIFIED` форма не перечитывает запись сама, чтобы не потерять введённые
      пользователем значения; пользователь закрывает окно и открывает запись снова.
