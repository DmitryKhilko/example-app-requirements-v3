# Классификатор типовых детальных функциональностей {#sf-classifier}

## Обзор {#overview}

Классификатор перечисляет типовые виды детальных функциональностей (SF) и для каждого вида — требования, которые обычно
в нём встречаются: данные (DR), функциональные (FR), нефункциональные (NFR) и интерфейсные (UI). Это контрольный список:
аналитик выбирает подходящий вид, убирает неприменимое и дописывает специфику своей функциональности.

Перечень не обязателен: пункт включается в SF, только если он к ней относится. Конкретные значения (поля, сроки, числа)
в классификаторе не приводятся, их задаёт аналитик. Бизнес-правила в классификатор не вынесены: по принятому упрощению
они записываются условиями внутри FR.

## Список и поиск (LIST) {#list}

- **Пример**: `SF-COUNTRY-LIST`
- **Назначение**: Постраничный просмотр записей справочника с поиском, сортировкой и фильтрацией.
- **Подключает**: `SF-G-DICT` (экран справочника), `SF-G-TABLE`, `SF-G-PAG`, `SF-G-SORT`, `SF-G-SEARCH`,
  `SF-G-FILTER`, `SF-G-COLUMNS`, `SF-G-SELECT`, `SF-G-TOAST`, `SF-G-SESSION`, формат ошибок.
- **Типичные DR**:
    - Состав полей списка и источник каждого поля
    - Поля, по которым разрешены поиск, сортировка и фильтрация
    - Сортировка по умолчанию и размер страницы по умолчанию
    - Допустимые значения размера страницы
    - Признак статуса записи, от которого зависит выборка (активна, неактивна)
- **Типичные FR**:
    - Система возвращает страницу записей и общее количество записей
    - Система сортирует записи по умолчанию и по выбранному полю и направлению
    - Система ищет по перечисленным полям: регистр, частичное совпадение, обрезка пробелов
    - Система фильтрует по статусу и другим атрибутам, фильтры сочетаются по условию «и»
    - Система не показывает записи, недоступные роли пользователя (например, неактивные)
    - Система сохраняет сортировку и фильтр при переходе между страницами
    - Система возвращает пустой результат, а не ошибку, если совпадений нет
    - Система отклоняет недопустимые параметры: размер страницы, поле сортировки
- **Типичные NFR**:
    - Время ответа при заданном объёме данных (95-й процентиль, условия измерения)
    - Максимальный размер страницы
    - Поведение поиска при росте объёма данных (индексы)
- **Типичные UI**:
    - Экран списка: таблица, строка поиска, фильтры, пагинатор, действия по роли
    - Состояния: загрузка, пустой результат, пустой справочник, ошибка загрузки
    - События: ввод в строку поиска, смена сортировки, фильтра и страницы, переход в карточку, кнопки действий
    - Сообщения: пустой результат, ошибка загрузки

## Карточка (READ) {#read}

- **Пример**: `SF-COUNTRY-READ`
- **Назначение**: Просмотр всех атрибутов выбранной записи, включая системные метаданные.
- **Подключает**: `SF-G-SESSION`, формат ошибок.
- **Типичные DR**:
    - Состав полей карточки
    - Системные метаданные: кто и когда создал и изменил запись
    - Версия записи (для последующего изменения)
    - Связанные данные, если они показываются (например, количество ссылок на запись)
- **Типичные FR**:
    - Система возвращает все атрибуты записи по идентификатору вместе с версией
    - Система сообщает, что запись не найдена, если её нет или она удалена
    - Система не показывает неактивную запись ролям без права её просмотра
    - Система показывает связанные данные, если они входят в карточку
- **Типичные NFR**:
    - Время ответа карточки (95-й процентиль)
- **Типичные UI**:
    - Экран или панель карточки: поля, метаданные, кнопки перехода к изменению, смене статуса и удалению по роли и
      статусу записи
    - Состояния: загрузка, запись не найдена, нет доступа, ошибка загрузки
    - События: переход к действиям, возврат к списку
    - Сообщения: запись не найдена, ошибка загрузки

## Создание (CREATE) {#create}

- **Пример**: `SF-COUNTRY-CREATE`
- **Назначение**: Добавление новой записи с проверкой формата и уникальности значений.
- **Подключает**: `SF-G-FORM`, `SF-G-TOAST`, `SF-G-SESSION`, формат ошибок.
- **Типичные DR**:
    - Перечень полей: тип, обязательность, формат, длина, значение по умолчанию
    - Ограничения уникальности и их область (с учётом удалённых записей)
    - Начальные значения: статус «активна», версия 1
    - Системные поля, которые заполняет система
- **Типичные FR**:
    - Система создаёт запись в активном статусе
    - Система проверяет обязательность, формат и длину полей и называет поле с ошибкой
    - Система проверяет уникальность и сообщает, какое значение уже занято
    - Система приводит значения к единому виду (регистр, пробелы)
    - Система записывает версию и метаданные создания
    - Система записывает действие в журнал аудита
    - При ошибке система не создаёт запись и не пишет в журнал
    - Система возвращает созданную запись
- **Типичные NFR**:
    - Создание записи и запись в журнал аудита выполняются в одной транзакции
    - Время ответа операции (95-й процентиль)
    - Повторная отправка той же операции не создаёт дубль (если это требуется)
- **Типичные UI**:
    - Форма создания: поля, подсказки формата, кнопки «Сохранить» и «Отмена»
    - Состояния: пустая форма, ошибка в поле, сохранение, значение уже занято
    - События: ввод в поле (проверка формата), сохранение, отмена с подтверждением потери данных
    - Сообщения: запись создана, значение занято, ошибка сохранения

## Редактирование (UPDATE) {#update}

- **Пример**: `SF-COUNTRY-UPDATE`
- **Назначение**: Изменение разрешённых полей существующей записи с контролем версии.
- **Подключает**: `SF-G-LOCK`, `SF-G-FORM`, `SF-G-TOAST`, `SF-G-SESSION`, формат ошибок.
- **Типичные DR**:
    - Перечень изменяемых и неизменяемых полей
    - Версия записи как основа оптимистичной блокировки
    - Метаданные изменения: кто и когда изменил
- **Типичные FR**:
    - Система изменяет только разрешённые поля и отклоняет попытку изменить неизменяемые
    - Система сравнивает версию и отклоняет изменение, если запись уже изменена
    - Система проверяет формат и уникальность изменённых значений
    - Система увеличивает версию записи
    - Система записывает в журнал аудита значения до и после изменения
    - Система возвращает обновлённую запись
- **Типичные NFR**:
    - При двух одновременных изменениях успешно только одно
    - Изменение записи и запись в журнал аудита выполняются в одной транзакции
    - Время ответа операции (95-й процентиль)
- **Типичные UI**:
    - Форма редактирования с текущими значениями, неизменяемые поля только для чтения
    - Состояния: изменение, конфликт версий (предложить обновить данные), ошибка в поле
    - События: сохранение, отмена, уход со страницы с несохранёнными изменениями
    - Сообщения: запись изменена, конфликт версий, ошибка сохранения

## Активация и деактивация (ACTIVATION) {#activation}

- **Пример**: `SF-COUNTRY-ACTIVATION`
- **Назначение**: Перевод записи между состояниями «активна» и «неактивна» без потери связей.
- **Подключает**: `SF-G-LOCK`, `SF-G-FORM`, `SF-G-TOAST`, `SF-G-SESSION`, формат ошибок.
- **Типичные DR**:
    - Поле статуса и допустимые значения
    - Разрешённые переходы между статусами
    - Метаданные смены статуса: кто и когда
- **Типичные FR**:
    - Система переводит запись по разрешённому переходу и отклоняет недопустимый (запись уже в этом статусе)
    - Система проверяет версию записи
    - Система не меняет остальные поля записи
    - Система сохраняет ссылки на неактивную запись в других подсистемах
    - Система скрывает неактивную запись от выбора и от ролей без права её просмотра
    - Система записывает действие в журнал аудита
- **Типичные NFR**:
    - Смена статуса и запись в журнал аудита выполняются в одной транзакции
    - Время ответа операции (95-й процентиль)
- **Типичные UI**:
    - Кнопка или переключатель в списке и карточке с учётом роли и текущего статуса
    - Диалог подтверждения с описанием последствий
    - Состояния: операция выполняется, конфликт версий, запись уже в этом статусе
    - Сообщения: статус изменён, конфликт версий, ошибка операции

## Удаление (DELETE) {#delete}

- **Пример**: `SF-COUNTRY-DELETE`
- **Назначение**: Логическое удаление неиспользуемой записи.
- **Подключает**: `SF-G-SELECT` (массовое удаление), `SF-G-CONFIRM`, `SF-G-TOAST`, `SF-G-SESSION`, формат
  ошибок.
- **Типичные DR**:
    - Признак удаления (логическое удаление)
    - Источники ссылок на запись в других подсистемах и способ их проверки
    - Освобождение уникальных значений после удаления
    - Срок хранения удалённых записей
- **Типичные FR**:
    - Система удаляет запись логически
    - Система запрещает удаление, если на запись есть ссылки, и сообщает причину
    - Система проверяет версию записи
    - Система освобождает уникальные значения удалённой записи (если так решено)
    - Система не показывает удалённую запись в списках и карточке
    - Система записывает действие в журнал аудита
- **Типичные NFR**:
    - Проверка ссылок и удаление выполняются в одной транзакции
    - Срок хранения удалённых записей
    - Время проверки ссылок при заданном объёме данных
- **Типичные UI**:
    - Кнопка удаления с учётом роли
    - Диалог подтверждения с предупреждением о необратимости
    - Состояния: удаление запрещено (есть ссылки), операция выполняется, ошибка
    - Сообщения: запись удалена, удаление запрещено из-за ссылок, ошибка операции

## Импорт из внешней системы (IMPORT) {#import}

- **Пример**: `SF-COUNTRY-IMPORT`
- **Назначение**: Загрузка эталонного перечня из внешней системы, предпросмотр расхождений и применение изменений.
- **Подключает**: формат ошибок, всплывающие сообщения; интерфейс внешней системы (`EI`).
- **Типичные DR**:
    - Источник данных и версия загружаемого набора
    - Задание импорта: идентификатор, статус, время, инициатор, отчёт по записям
    - Соответствие полей источника и справочника
    - Виды расхождений: добавить, изменить, без изменений, конфликт
    - Срок хранения заданий и отчётов
- **Типичные FR**:
    - Система запускает импорт в фоне и возвращает идентификатор задания
    - Система получает данные из внешней системы и сравнивает их с текущими
    - Система показывает предпросмотр расхождений до применения
    - Система применяет изменения только после подтверждения администратора
    - Система не допускает запуск второго импорта, пока выполняется первый
    - Система повторяет обращение при сбое внешней системы и завершает задание ошибкой, если повторы исчерпаны
    - Система формирует отчёт по каждой записи
    - Система записывает применение изменений в журнал аудита
    - Система решает, чьи данные приоритетнее при расхождении: источника или ручных правок
- **Типичные NFR**:
    - Время работы импорта при заданном объёме данных
    - Повторы с растущей задержкой при недоступности внешней системы
    - Ограничение размера пакета и таймаут обращения
    - Применение пакета изменений атомарно
    - Срок хранения заданий и отчётов
- **Типичные UI**:
    - Экран запуска и статуса задания, предпросмотр расхождений с фильтром по виду различия и выбором записей, отчёт
    - Состояния: не запущен, выполняется, завершён, ошибка источника, различий нет
    - События: запуск, обновление статуса, выбор записей, применение, отмена
    - Сообщения: импорт запущен, импорт завершён, источник недоступен, различий нет

## Выгрузка в файл (EXPORT) {#export}

- **Пример**: `SF-COUNTRY-EXPORT`
- **Назначение**: Формирование файла с записями по текущим условиям.
- **Подключает**: формат ошибок, всплывающие сообщения.
- **Типичные DR**:
    - Перечень выгружаемых полей и порядок колонок
    - Формат файла, кодировка, разделитель, имя файла
    - Ограничение объёма выгрузки
- **Типичные FR**:
    - Система формирует файл по текущим условиям поиска и фильтрации
    - Система выгружает только данные, доступные роли пользователя
    - Система формирует большой файл в фоне и сообщает, когда он готов
    - Система сообщает, если выгружать нечего
    - Система записывает выгрузку в журнал аудита (если это требуется)
- **Типичные NFR**:
    - Максимальный объём выгрузки
    - Время формирования файла при заданном объёме
    - Срок хранения готового файла
- **Типичные UI**:
    - Кнопка выгрузки и выбор формата
    - Состояния: формируется, готов, ошибка, выгружать нечего
    - Сообщения: файл готов, ошибка формирования, нет данных для выгрузки
