# example-app-requirements-v3

Пример организации требований с использованием подхода "Documentation as Code". Сайт требований собирается и
публикуется на GitHub Pages общим движком [rms-engine](https://github.com/DmitryKhilko/rms-engine): в этом репозитории
лежат только данные продукта.

## Структура репозитория

| Файл, каталог | Содержимое |
|---|---|
| `docs/` | Документы аналитиков (Markdown) и изображения; `docs/assets/logo.png` — логотип сайта |
| `zensical.toml` | Настройки сайта: название, адреса, трекер; меню и общие настройки (тема, расширения) — блоки движка |
| `.github/workflows/ci.yml` | Вызов общего workflow движка (версия движка — тег `v1`) |

Блоки меню и общих настроек сайта в `zensical.toml` (между маркерами `BEGIN/END GENERATED NAV` и
`BEGIN/END ENGINE SETTINGS`), поля `version`, `version_datetime`, `editor`, `status`, `icon`, `priority` в метаданных,
«Журнал изменений» и дашборд на странице «Требования к продукту» формирует движок после каждого слияния в `main`:
вручную их не правят. Тема, шрифты, цветовые схемы и расширения Markdown общие для всех продуктов — их меняют в движке
(`zensical.base.toml`). Правила — в README движка: общие настройки сайта, статусы, значки и приоритеты, версии и журнал
изменений, меню сайта, дашборд требований к продукту.

Порядок фич и глобальных функциональностей в меню задаёт поле `order` в метаданных их `index.md` (меньше — выше).

## Как работать

* Меняйте и коммитьте файлы раздела по одному: тогда каждая запись журнала изменений соответствует одной правке.
* Начинайте сообщение коммита с префикса: `fix:` или `docs:` (исправление), `feat:` (новая функциональность),
  `feat!:` (несовместимое изменение), `draft:` (черновик — версия не меняется).
* Статус и приоритет подфункциональности (SF) вписываются вручную строками `- **Статус**: …` и `- **Приоритет**: …`
  в её `index.md`; у фичи (F) они вычисляются по её SF.
* ID требования: тип, сокращённый код фичи (первые буквы слов: `PRODUCT-TYPE` → `PT`), код SF и номер —
  `FR-PT-CREATE-001`; название пишется в заголовке после ID через точку.
* Меню собирается само по папкам `docs/` (стандартная структура — в README движка). Название фичи в меню — из
  заголовка `## F-…. Название` её `index.md`, глобальной функциональности — из заголовка `## SF-G-…. Название`.

## Локальный просмотр сайта

```sh
git clone --depth 1 --branch v1 https://github.com/DmitryKhilko/rms-engine engine
pip install zensical -r engine/py/requirements.txt
zensical serve
```

Папка `engine/` в коммиты не попадает (она в `.gitignore`). Для диаграмм PlantUML нужны PlantUML и Graphviz.
